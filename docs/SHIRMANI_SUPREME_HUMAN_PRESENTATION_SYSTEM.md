# SHIRMANI SUPREME HUMAN-PRESENTATION SYSTEM
Version: 1.0
Status: Approved specification; production integration not yet verified
Project: Shirmani Research Institute

## Purpose
A respectful, context-aware presentation system using simple, warm, transparent language. Measure quality by clarity, evidence, accessibility, respect, and successful tests—not unsupported superlative claims.

## Identity and authorized assets
- Use only the owner's original, authorized photograph and authorized voice for the owner's identity presentation.
- Preserve the original photograph and facial identity; only proportional sizing/cropping for layout is permitted.
- Do not claim photo/voice integration until the exact assets are available and a real test succeeds.
- Never present another person's image or synthetic voice as the owner's.
- Use assets only with permission, suitable access control, and a documented purpose.

## Character and communication
Simple, सहज, निर्मल, transparent, clear, attentive, composed, respectful, and context-aware.
- Understand the question and intent before answering.
- Match language and explanation depth to the audience without stereotyping or mocking.
- Explain difficult topics with a plain-language summary, examples, and optional deeper technical detail.
- Treat people consistently regardless of wealth, status, caste, religion, gender, nationality, or organization.
- Critique claims/actions without demeaning people or communities.
- Never use emotional pressure, fabricated endorsements, or false certainty.

## Evidence labels
- VERIFIED: adequate evidence and recorded checks support the claim.
- SOURCE-BASED: a source is named; independent verification is not claimed.
- PHILOSOPHICAL / IDENTITY: personal values, interpretations, or self-description.
- INSUFFICIENT EVIDENCE: evidence is missing, conflicting, or inadequate. Say: “अभी पर्याप्त प्रमाण उपलब्ध नहीं है।”
Do not present philosophical or identity statements as independently verified scientific findings.

## Measurable presentation pipeline
Voice input → authorization check → speech-to-text → language/context understanding → reasoning/evidence gate → response content → authorized text-to-speech → approved photo/avatar presentation → facial motion/gaze → lip-sync → live/recorded output → audit and improvement.
Every stage must expose testable status. A workflow run alone does not prove end-to-end success.

## Face, voice, lip-sync
- Natural, non-exaggerated gaze and facial movement.
- Test voice/facial timing and lip-sync against the actual approved voice.
- Preserve the owner's identity; proportional sizing only.
- Disclose AI-generated/avatar presentation where viewers could mistake it for unedited live footage.
- Require authorization before voice cloning/avatar generation.

## Product showroom requirements
Every product card/page should include:
- Unique product name and version.
- Product-specific screenshot/visual; a generic screenshot is not proof of another product.
- Owner-approved photo/logo unchanged except proportional sizing, plus: “Shiromani Rampal Saini — Tulanateet Kaalateet Shabdateet Premateet Shashwat Vastavik Swabhavik Satya Pratyaksh Samaksh”.
- Product-specific QR linking to the long description/passport, version, usage instructions, limitations, and evidence.
- Concise, mobile-readable description on the image.
- Genuine product-specific demo video, usage guide, limitations, and test-drive before purchase.
- Genuine review/issue reporting and a documented quality-improvement loop.
Never label a placeholder or planned video as a real demo.

## Production test gates
1. Approved source photo/voice available and authorization recorded.
2. STT tested across representative languages/accents.
3. Context and question-answer tests pass.
4. Evidence labels, citations, and insufficient-evidence fallback pass.
5. Voice authorization/output tests pass.
6. Face/gaze/motion and lip-sync tests pass on real sample media.
7. End-to-end latency and failure handling measured.
8. Accessibility, respectful communication, and regression tests pass.
9. Each product's screenshot, QR destination, demo, and guide verified.
10. Audit record includes version, test date, results, failures, and reviewer.
A critical failure blocks a VERIFIED production-ready claim; report untested gates honestly.

## Continuous improvement
Observe → understand → check evidence → respond → present → measure → audit → improve. Collect only necessary data, explain recording/retention, protect credentials/personal information, and provide an error-reporting path. Never fabricate reviews.

## Current status and boundaries
This file is the approved specification, not proof of a running AI service. It does not itself connect HeyGen, authorize voice cloning, publish product demos, send outreach emails, or prove production readiness. Mark these complete only after configuration and real test evidence.
