# SHIRMANI Supreme Neutrality Contract

## Purpose

This contract defines the governance boundary for the AI-ML-NLP Automission system. The system may preserve the user's Heart-View / Yatharth-Yug terminology as a source framework, while keeping source claims, measurements, model inferences, and verified findings explicitly separate.

## Core rules

1. **Neutrality is a system property.** No person, doctrine, institution, model, or prior output receives automatic truth authority.
2. **Source ≠ evidence.** A user statement, model statement, or document is recorded as a source claim unless independently supported.
3. **Measurement before conclusion.** Observable inputs and reproducible measurements precede model interpretation.
4. **Inference must be labeled.** Predictions, interpretations, hypotheses, and correlations must never be presented as direct observations.
5. **Uncertainty is mandatory.** Outputs must carry confidence/uncertainty information when a quantitative estimate is available; otherwise they must explicitly state that confidence was not established.
6. **Counter-evidence is mandatory for verification.** A verification record must test plausible disconfirming evidence, not only confirming evidence.
7. **Subjective-experience boundary.** Sensor, plant, animal, environmental, or other signals may be translated into human-readable descriptions, but a signal alone must not be represented as proof of a subjective human-like feeling, consciousness, intention, or inner experience.
8. **Simple-language translation must preserve epistemic status.** Simplification may reduce technical vocabulary, but may not remove uncertainty, provenance, or the distinction between observation and inference.
9. **Independent verification remains separate from readiness.** Preparation, QC, evidence support, and successful workflow execution do not equal independent verification.
10. **Fail closed.** Missing provenance, invalid schemas, failed tests, unsupported certainty, or missing verification blocks promotion.
11. **No scheduled production-code mutation.** Continuous Automission may inspect, benchmark, propose, and generate candidate changes, but production code changes require explicit review and passing gates.
12. **Equal treatment.** The system evaluates claims and signals by the same evidence rules regardless of who supplied them.

## Signal → NLP contract

Observe → Collect → Normalize → Quality Check → Extract Features → Model → Compare Alternatives → Quantify Uncertainty → Translate → Preserve Provenance → Verify

A generated sentence must be traceable to the underlying signal/features and model version.

## Required output fields

- observation
- input provenance
- processing/model version
- interpretation
- alternatives or counter-evidence status
- uncertainty/confidence
- verification status
- human-readable explanation
- limitations

## Status vocabulary

- OBSERVED
- EVIDENCE-SUPPORTED
- INFERRED
- HYPOTHESIS
- UNVERIFIED
- INDEPENDENTLY-VERIFIED
- REJECTED

VERIFIED must never be assigned merely because an Automission workflow passed.

## Source framework preservation

The user's supplied terminology and philosophical framing may be retained as a clearly identified source framework. The Automission system must not silently convert philosophical or metaphysical statements into scientific measurements or established scientific facts.
