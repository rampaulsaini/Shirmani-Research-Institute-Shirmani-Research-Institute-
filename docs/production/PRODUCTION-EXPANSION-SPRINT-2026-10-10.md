# Production Expansion Sprint — 2026-10-10

## Operating rule

Automission must produce customer-visible artefacts, not just workflow runs or verification records. The four business stages are:

1. **Institute / Discovery** — choose a real customer problem, define intended user, source evidence, and acceptance criteria.
2. **Factory / Build** — create the working tool, product-specific visual, usage guide, demo script, and sample output.
3. **QC / Release gate** — test the actual artifact, record defects and limitations, and block dispatch for critical failures.
4. **Showroom / Sale** — publish only the working artifact with a clear price or quote basis, demo, terms, and enquiry/order path.

A product is not counted as production-complete because a name, plan, workflow, poster brief, or checklist exists.

### Lane B — Product media minimum release package

Every public product record should link to:
- a unique product ID and stable product page;
- a product-specific cover image or an explicit 'not-created' state;
- concise on-image description and readable mobile scaling;
- QR destination and a long-form product passport;
- a demo video or a clearly labelled storyboard until a real video exists;
- a VIP screenshot or a clearly labelled screenshot brief until a real screenshot exists;
- usage guide, supported inputs/outputs, limitations, price/offer, and enquiry/order route;
- QC status and customer feedback/improvement history.

Do not represent a storyboard as a video, a QR destination preview as a generated QR image, a brief as a screenshot, or a planned feature as a working capability.

### Lane D — Security as a production prerequisite

Use layered, authorised security work:
1. repository permissions, branch protection and secret hygiene;
2. dependency/code scanning and workflow least privilege;
3. input validation, output escaping, and safe handling of customer briefs;
4. release artefact checks, backup/recovery instructions, and incident log.

Only report a scan or control as complete when the corresponding run/configuration or evidence is available. No unauthorised penetration testing or contact with third-party systems.

## Automission job contract

Each scheduled job must do useful bounded work and write a durable output:
- **Input:** one product, defect, customer segment, or deliverable task.
- **Action:** build/update a real artefact or a human-review-ready outreach draft.
- **Output:** committed file, generated asset, reproducible test result, or dated prospect record.
- **Quality:** automated tests plus an explicit human review gate where needed.
- **Telemetry:** produced, updated, blocked, failed, and released counts, with artifact links.
- **Safety:** no external email/message, purchase, deployment, or public claim without the relevant authorisation.

A successful workflow is not itself proof of a finished product. Independent verification remains a release/QC gate, not the main production activity.

## Weekly metrics

Record a dated baseline first; never invent a starting count.

| Metric | Definition |
|---|---|
| Working tools added | Tools that execute the documented core use case and have a reproducible example |
| Product media completeness | Published products with actual image, actual demo video, usage guide, QR destination, passport, price/quote basis, and enquiry path |
| QC pass rate | Products passing the stated release tests divided by products tested |
| Public releases | New or improved usable artefacts linked from the public showroom |
| Qualified prospects | Organisations with a relevant use case and a verified official contact source |
| Outreach sent | Human-confirmed sends only |
| Replies / quotes / paid orders | Count only with dated evidence |
| Customer feedback fixes | Feedback-linked changes merged and described |

## Release policy

- Keep the four-stage status visible: DISCOVERY, BUILDING, QC_BLOCKED or QC_PASSED, PUBLISHED.
- Do not dispatch products with unresolved critical defects.
- Customer reviews may inform prioritisation but cannot automatically override safety, privacy, factuality, or legal requirements.
- Use official public organisational channels; respect terms, rate limits, privacy, and opt-outs.
- Never claim universal coverage, millions of active agents, 850-crore capacity, sales, income, or security certification without measurable evidence.
