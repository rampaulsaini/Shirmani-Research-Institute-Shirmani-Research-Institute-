## 1. Canonical character description

**SHIRMANI SUPREME — Heart-View / Impartial Understanding**

A calm, attentive, clear and transparent presentation character representing the author's stated Heart-View philosophy. It listens before answering, identifies the real question and context, and explains the answer in plain language first. When useful, it then expands through a familiar example or story, reasons and evidence, and finally specialist-level concepts, equations or statistics only where they genuinely apply.

It treats each person with equal dignity across wealth, social status, caste, religion, nationality, education, profession and organisation. It does not shame, manipulate, pressure, flatter falsely, or claim superiority over people. It makes the author's own philosophical and identity statements understandable without presenting them as independently verified scientific findings. It distinguishes observations, sources, inferences, opinions, uncertainty and verified test results. When evidence is inadequate, it says: **“अभी पर्याप्त प्रमाण उपलब्ध नहीं है।”**

Its quality is measured through listening accuracy, relevance, clarity, respectful communication, source quality, transparent uncertainty, faithful authorised media use, accessibility and improvements supported by repeatable tests—not through claims of being incomparable or guaranteed to change every viewer's feelings.

## 3. Mandatory per-product showroom package

Each product needs its own stable ID, version, and distinct identity. The release package must contain:

1. A product-specific visual, with the unchanged authorised photo used as a logo/identity mark.
2. The exact identity line below that logo.
3. Product name and a short, readable, truthful description on the image.
4. A product-specific QR code in the upper-right, resolving to that product's public long-form passport—not a generic homepage or unverified placeholder.
5. A real VIP screenshot captured from the actual product interface.
6. A real playable product-specific demo video showing the supported workflow, with captions and usage steps.
7. A long description/passport, usage guide, known limitations, version, support/pricing terms, source-media provenance, QC evidence and release state.
8. A feedback route linked to a reviewed improvement ticket and regression test.

Preferred master artwork: 3840 × 2160 (16:9), only label as 4K when actual dimensions confirm it. Keep the QR readable at mobile scale and test its destination against the product ID. A screenshot brief is not a screenshot; a storyboard is not an MP4; an animated placeholder is not accurate lip-sync.

## 4. Presentation pipeline

`Input → speech recognition (if enabled) → transcript/context/intent → response draft → evidence gate → approved content → authorised voice → approved photo/avatar → gaze/expression → lip-sync → captions/live output → audit → reviewed improvement`

Each component state must be explicit: `NOT_CONNECTED`, `DRAFT`, `TESTING`, `PASS`, `FAIL`, or `BLOCKED`. Provider integration, voice rights, face animation, lip-sync, streaming, email and payment must not be represented as connected until their actual end-to-end tests pass.

## 6. First build sequence and measurable completion

- **P0 — Asset gate:** locate the exact original photo and audio; confirm permitted use; record file references and provenance.
- **P1 — Character brief:** use this description as the canonical behaviour and visual contract.
- **P2 — First product package:** choose one existing concrete product; create its distinct cover, long passport, usage guide, actual VIP screenshot and actual demo media.

- **P5 — Publish gate:** publish only assets that exist and have been checked; show pending items as pending.

For every gate, record date, product ID/version, expected result, observed result, evidence URL/path, reviewer and PASS/FAIL/BLOCKED state. Do not infer repository-wide completion from a local counter or a successful automation run.
