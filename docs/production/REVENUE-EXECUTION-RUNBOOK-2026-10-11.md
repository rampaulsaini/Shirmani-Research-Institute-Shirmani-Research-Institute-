## 2. Sell only what can be delivered now
Initial service: Hindi/English writing, editing, research-summary structuring, and website/blog drafts. Do not sell connected AI research, independent scientific verification, live avatar, lip-sync, MP4 rendering, bulk email, or payment integration unless implemented and tested.

Existing proposed pilot price references in the repository include ₹499, ₹999, ₹1,499, ₹1,999 and ₹2,999 for different scopes. These are proposals, not validated market rates. Confirm word count, language, audience, source expectations, deadline, revisions, rights, and payment terms in writing before work begins. Avoid conflicting menus: the price agreed in the client-specific quote is authoritative.

## 3. Daily execution checklist
1. Open the public service page on mobile and check every link.
2. Review Hindi and English samples for accuracy, originality, clarity, and publication permission.
3. Identify 10 organisations whose public work genuinely matches the service, using official websites/contact pages.
4. Record organisation, official URL, publicly stated need, relevant team, contact route, research date, and fit reason.
5. Prepare five individual messages with the Outreach Studio; do not send generic bulk spam.
6. Human-review every draft for accuracy, relevance, privacy, respect, and a clear opt-out.
7. Send only through a verified, authorised channel. Record a send timestamp/reference only after actual sending.
8. Track replies, qualified enquiries, proposals, accepted work, delivery, revisions, and payment separately.
9. For accepted work, agree scope in writing; use the Source Ledger for research and Deliverable Studio for the output pack.
10. QC each deliverable for scope match, language, originality, source links, limitations, format, and privacy.

## 4. Prospect pipeline fields
`prospect_id, organisation, sector, official_url, public_need, contact_route, checked_on, offer, draft_status, sent_at, reply_status, proposal_amount, order_confirmed_at, payment_received_amount, delivery_due, delivered_at, acceptance_status, follow_up_due, opt_out`

Keep prospect and payment records private. Never commit personal contact data, credentials, private client material, or payment references to the public repository.

## 5. Funnel metrics
Count only evidence-backed events: prospects researched; official contact routes checked; tailored drafts prepared; drafts approved; messages actually sent; replies; qualified enquiries; proposals; confirmed orders; payments received; accepted deliverables; revisions and complaints.

Revenue means cleared payments actually received, not proposed prices, invoices, or verbal interest. Conversion rate = next-stage count / prior-stage count × 100; show N/A when the denominator is zero.

## 6. Four-stage product chain
**Institute / Research → Factory / Build → QC / Release gate → Showroom / Sale**

For every product record product ID/name/version, purpose, target user, actual working features, demo route, real screenshot, product-specific MP4 state (`SCRIPT_ONLY`, `RECORDING_PENDING`, `RENDERED`, `PUBLISHED`), usage guide, limitations, passport/QR destination, price/terms, defects/fixes, reviewer, release decision, and commercial state (`DEMO_ONLY`, `AVAILABLE_FOR_SCOPED_WORK`, `ORDER_CONFIRMED`, `PAID`, `DELIVERED`).

A storyboard is not an MP4; a catalogue identity is not a finished product; a workflow run is not a sale.

## 7. Security-first operating boundaries
- Use least-privilege repository and workflow permissions.
- Never place tokens, provider keys, prospect data, or client data in source code or public logs.
- Run the existing read-only security baseline and review findings before adding integrations.
- Perform authorised testing only; do not test third-party systems without written permission.
- Keep outbound messages human-approved and respect opt-outs.
- For voice/face generation, record rights and explicit authorisation; do not impersonate others.
- Before collecting payments or personal data, document provider, privacy, refund, and retention terms.
