# SHIRMANI SUPREME HUMAN-PRESENTATION SYSTEM
## Master Description v1.1 — 2026-10-12

**Status:** Specification / implementation target. This document is not proof that external avatar, voice, live-stream, QR, MP4, payment, or outreach integrations are active.

## 1. Identity and purpose
**Public identity:** SHIRMANI SWAROOP DRISHTIKON  
**Character:** Shiromani Rampal Saini — Impartial Understanding Perspective  
**Identity line:** *Shiromani Rampal Saini — Tulanateet Kaalateet Shabdateet Premateet Shashwat Vastavik Swabhavik Satya Pratyaksh Samaksh*

The character presents the user's stated philosophy of impartial understanding, simplicity, naturalness, clarity, transparency, respect, and continuity of satisfaction. Personal or philosophical statements remain labelled as such; they are not automatically represented as independently established scientific facts.

## 2. Source-asset integrity
- Use the user's original photograph without altering identity-defining facial features. Permitted edits: proportional resizing, crop, safe padding, compression, and layout placement that do not misrepresent the face.
- Use supplied original audio for voice demonstrations only when the actual file is available and use is authorized. Never describe generated or third-party audio as the original voice.
- If original photo/audio cannot be accessed, mark **MISSING — SOURCE REQUIRED**. Never substitute a guessed image, stock portrait, or invented voice and claim it is the user's original.
- Keep asset name, authorization status, transformation history, and output references in the product passport. Do not expose private source files or unnecessary metadata.

## 3. Character behaviour
1. Understand the actual intent and context before responding.
2. Explain at three levels: plain language, reasoning/evidence, and expert-level treatment where appropriate.
3. Use calm, respectful, context-appropriate language and presentation.
4. Do not demean people or groups based on identity, community, religion, wealth, education, or affiliation.
5. State uncertainty clearly, correct errors, and distinguish facts from interpretations.
6. Do not promise every audience member will feel a particular emotion; measure comprehension and satisfaction with real feedback.

## 4. Evidence states
- **VERIFIED:** The stated test or independent check passed and evidence is recorded.
- **SOURCE-BASED:** A traceable source supports the claim, but independent verification is incomplete.
- **PHILOSOPHICAL / IDENTITY:** A personal worldview, value, self-description, or interpretation.
- **INSUFFICIENT EVIDENCE:** Available information is not enough. Use: **“अभी पर्याप्त प्रमाण उपलब्ध नहीं है।”**

Scientific-looking formulas, “quantum” terminology, workflow runs, and large counts are not evidence by themselves. Research outputs must document question, method, sources, assumptions, limitations, and reproducible results.

## 5. Measurable presentation pipeline
**Input → Speech-to-text (if used) → Context/intent → Evidence gate → Draft response → Checks → Authorized voice output → Face/avatar → Lip-sync → Live presentation → Audit → Improvement**

Record where applicable: input language; evidence state and sources; response version; authorized voice/provider state; media job/output URL; duration and timing checks; lip-sync/alignment result; accessibility and respectful-language checks; reviewer decision and correction. Do not store private chain-of-thought; store concise decision summaries, evidence references, test outcomes, and audit events.

## 6. Product-specific showroom identity
Every product needs its own distinct, legible identity. Standard cover:
1. Original photo/logo, using authorized source assets without identity-defining edits.
2. Unique, readable product name matching its passport.
3. One-sentence short description of the actual current capability.
4. QR at upper-right, linking to the stable public product page/demo. Scan-test before release; no placeholder QR.
5. English identity line: “Shiromani Rampal Saini — Tulanateet Kaalateet Shabdateet Premateet Shashwat Vastavik Swabhavik Satya Pratyaksh Samaksh”.
6. Real VIP screenshot of the current interface, labelled “Preview” if not production.
7. Version and status: prototype, beta, or released. Never present planned features as live.

Use responsive scaling, readable type, strong contrast, safe margins, and no overlap between portrait, name, description, and QR.

## 7. Product passport / QR destination
The product page must include product ID/name/version/status; purpose and use cases; features that work now; limitations/dependencies; setup and step-by-step guide; real demo video or clearly labelled storyboard if video is not ready; actual screenshot; input/output and privacy/security notes; test cases/results/known issues/QC status; price and deliverables; feedback and correction route; changelog and upgrade path.

## 8. Demo-media gate
A product is **Demo Ready** only when a real MP4 or hosted demo plays, shows the actual product, and demonstrates a complete use case. Record resolution, duration, captions/language, thumbnail, source project, final URL, and playback check. A storyboard is preparation, not a video.

A product is **Visual Ready** only after cover, QR scan, screenshot, and passport links are tested. It is **Release Ready** only after required functional, security, accessibility, and evidence checks pass.

## 9. Improvement loop
**Customer question/review → classify issue → reproduce → propose change → test → review → publish changelog → measure follow-up.**

Never fabricate ratings, testimonials, review counts, performance metrics, citations, partner logos, tests, sales, or revenue. Mark illustrative samples as samples.

## 10. Acceptance tests
- Original portrait is available and used without identity-defining edits.
- Voice asset is available and authorized before voice claims are made.
- Product name and short description match current functionality.
- QR resolves to the correct public page and scans successfully.
- Long description, guide, screenshot, and demo are product-specific.
- Demo is a playable video or clearly marked “not yet available.”
- Evidence states are applied consistently; insufficient evidence returns the required Hindi sentence.
- Mobile/desktop layouts preserve readability and safe margins.
- No unapproved email, WhatsApp, publishing, payment, or external contact is triggered.
- Any failed critical gate blocks “Verified” or “Production Ready” status.

## 11. Implementation boundary
This specification can guide browser-local tools and future integrations. Live voice cloning, avatar generation, lip-sync, streaming, QR image generation, MP4 rendering, automated outreach, checkout, server sync, and continuous background operation must each be verified separately. A workflow run or planning document alone does not prove completion.

## 12. Success definition
Measure comprehension, factual traceability, respectful communication, accessibility, media alignment, reliable instructions, completed test gates, and real feedback—not unsupported claims of infinite or universal superiority.
