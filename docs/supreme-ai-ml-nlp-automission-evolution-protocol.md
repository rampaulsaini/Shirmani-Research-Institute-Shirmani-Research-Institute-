# Supreme AI–ML–NLP Automission Evolution Protocol

## Objective

Extend the existing Supreme AI–ML–NLP–Automission control plane without weakening its evidence-first and fail-closed guarantees.

## Current implementation baseline

The repository already provides:

- observable-signal normalization;
- quality and variability analysis;
- multimodal/source diversity accounting;
- uncertainty and limitation reporting;
- simple-language NLP rendering;
- deterministic fingerprints;
- Automission improvement planning;
- independent-verification governance;
- five-minute scheduled auditing.

The baseline does **not** treat a model interpretation as proof of subjective experience.

## New regression gate

factory/supreme_nlp_benchmark.py provides a deterministic synthetic regression suite.

The benchmark checks:

1. stable-pattern classification;
2. moderate-variability classification;
3. high-variability classification;
4. uncertainty-preserving language;
5. deterministic output fingerprints.

The benchmark is intentionally labelled as a **synthetic internal regression test**. Its score must never be presented as real-world scientific accuracy.

## Production evolution path

### Stage A — Measurement

Register validated sensors and data sources with:

- timestamp;
- calibration metadata;
- sampling rate;
- units;
- quality score;
- provenance;
- baseline;
- environmental context.

### Stage B — Dataset

Build versioned labelled datasets with:

- positive examples;
- negative examples;
- ambiguous examples;
- counter-evidence;
- independent test splits;
- domain and language metadata.

### Stage C — ML evaluation

For each model/version report, where applicable:

- precision;
- recall;
- F1;
- confusion matrix;
- false-positive rate;
- false-negative rate;
- calibration error;
- robustness;
- distribution-shift performance;
- reproducibility.

### Stage D — NLP fidelity

Measure whether the natural-language explanation faithfully preserves:

observation → inference → uncertainty → evidence → limitation

The language layer must not silently strengthen an inference into a factual claim.

### Stage E — Independent verification

A second procedure, dataset, implementation, or evaluator must independently test important claims.

Preparation/QC and independent verification remain separate states.

### Stage F — Controlled improvement

Automission may:

- identify weaknesses;
- generate proposals;
- run tests;
- compare baselines;
- produce artifacts;
- recommend rollback.

Scheduled automation must not silently promote unverified production-code changes.

## Biological / plant / non-living signal research

Signals from living or non-living systems can be computationally analysed when they are measurable and appropriately collected.

The system may translate observable patterns into simple language, but the following distinction is mandatory:

**signal ≠ inference ≠ subjective experience**

A statement about emotion, consciousness, pain, intention, or subjective experience requires an operational definition, appropriate evidence, independent testing, and explicit uncertainty.

## Supreme accuracy principle

“Supreme accuracy” remains the engineering direction, not a pre-certified fact.

The system becomes stronger by increasing:

**measurement quality + dataset quality + model quality + calibration + independent replication + auditability**

rather than by declaring certainty in advance.

## Automission cycle

Observe → Collect → Normalize → Analyze → Reason → Execute → Test → Verify → Audit → Learn → Improve

Every cycle should leave a machine-readable trace.

## Success condition

A cycle is successful only when the relevant gates pass. If evidence is insufficient, the correct system behaviour is to say that evidence is insufficient and request better measurement rather than manufacture certainty.
