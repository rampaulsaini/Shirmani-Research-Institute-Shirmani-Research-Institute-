# Shirmani Research Institute — Revenue Execution Pack
**Prepared:** 2026-10-16  
**Purpose:** Turn the currently available Hindi/English writing and source-based research services into a measurable, evidence-led client acquisition process.

## 1. Current verified starting point

The repository contains a public writing/research enquiry flow and service-page materials. The enquiry tool creates a draft brief; it does **not** submit an order, send email, accept payment, or persist a central server-side lead automatically. Treat every enquiry as unsubmitted until a human confirms receipt.

The repository's public service menu has proposed pilot rates, but issue [#2462](https://github.com/rampaulsaini/Shirmani-Research-Institute-Shirmani-Research-Institute-/issues/2462) documents conflicting menus and requires owner approval/reconciliation before quoting a final price. Do not present proposed rates as market-validated or final until that gate is cleared.

Baseline from the revenue ledger/context at preparation: **0 verified outreach messages, 0 qualified leads, 0 accepted quotes/orders, 0 completed paid deliveries, and ₹0 verified receipts**. Update only with evidence.

## 2. Sell only deliverables that can be delivered now

### Offer A — Hindi/English editing and proofreading
- Client supplies a draft and intended audience.
- Deliver: edited document, concise change notes, and one agreed revision round.
- Before quote: word count, source/reference needs, turnaround, file format, and revision scope.

### Offer B — Article, website or blog content
- Deliver: agreed outline, one draft, title/heading structure, and one agreed revision round.
- Before quote: target audience, objective, tone, length, language, SEO requirements (if any), source expectations, and deadline.

### Offer C — Source-based research brief
- Deliver: scoped question, summary, key findings, source list with links, limitations/uncertainties, and clearly separated evidence versus interpretation.
- Before quote: research question, geography/time period, acceptable sources, depth, citation style, length, and intended use.
- Do not promise exhaustive coverage, professional legal/medical/financial advice, or certainty beyond the sources.

## 3. Pricing control — mandatory before a binding quote

1. Owner reviews the cost/pricing worksheet and chooses the approved public pilot menu.
2. Reconcile all public service pages, outreach templates and quote generators to that menu; classify unrelated digital-product prices separately.
3. State what each price includes, word/source limits, revisions, turnaround, taxes if applicable, and payment milestones.
4. Until approval is recorded, use: **“We will confirm a written quote after reviewing scope, deadline and deliverables.”**
5. Never imply a client has accepted a quote, a payment was received, or a service was delivered without records.

This is a target, not a claim of work already done.

| Day | Action | Evidence to save | Completion measure |

| 1 | Approve the service menu and cost floor; check the public enquiry route | Owner approval note; route/test record | 1 approved menu; 1 documented route test |

If an action is not completed, record **0** and its blocker; do not mark a planned action complete.

### Short follow-up (send once, if appropriate)

**Rules:** Use only verified official contact channels; personalise the first sentence with a checked fact; obey applicable privacy, anti-spam and platform rules; include a truthful identity and opt-out; do not mass-send or claim a prior relationship. These are drafts, not sent messages.

## 6. Prospect qualification checklist

A prospect is **qualified** only when all required evidence is recorded:
- Organisation and official website verified.
- Relevant team/contact channel found on an official page.
- Specific, plausible writing/research use case identified from public evidence or the prospect's reply.
- Need, deliverable, decision path and approximate timeline are confirmed or explicitly marked unknown.
- Contact is appropriate under applicable outreach rules.

A public email address alone is not a qualified lead. Do not infer budget, need, procurement status, or willingness to buy.

## 7. Evidence-based funnel ledger

Use one row per organisation/opportunity. Do not store unnecessary personal data.

| Field | Allowed value / instruction |
|---|---|
| Prospect ID | Stable internal ID; avoid personal identifiers |
| Organisation | Verified legal/public name |
| Official source URL | Page supporting identity, fit or contact |
| Fit hypothesis | One sentence; mark as hypothesis until confirmed |
| Contact channel | Official public channel only |
| Verification date | YYYY-MM-DD |
| Message status | Draft / Approved / Sent / Bounced / Replied |
| Sent evidence | Timestamp plus thread/message reference; blank if not sent |
| Qualification | Unreviewed / Qualified / Not qualified |
| Need confirmed | Yes / No / Unknown, with evidence note |
| Quote | Draft / Sent / Accepted / Declined; link/version |
| Order and delivery | Not started / In progress / Delivered / Accepted; evidence link |
| Invoice/payment | Not issued / Issued / Paid / Failed; transaction or receipt evidence |
| Verified receipts (INR) | Actual settled amount only; never pipeline value |
| Next action/date | Specific owner and date |
| Blocker | Approval, contact, budget, capacity, technical, or other |

Keep these separate: prospects reviewed, qualified leads, messages sent, replies, discovery calls, quotes sent, accepted orders, deliveries accepted, invoices issued, payments settled, refunds, and net verified receipts.

## 8. Weekly dashboard and success criteria

Report counts and conversion rates only when denominators are known:
- Messages sent / messages approved
- Replies / messages delivered
- Qualified leads / prospects reviewed
- Quotes sent / qualified leads
- Accepted orders / quotes sent
- Accepted deliveries / orders due
- Verified receipts and refunds from transaction evidence
- Median response time and on-time delivery rate once enough records exist

**First experiment success is operational learning, not guaranteed revenue:** a reconciled approved menu, tested enquiry path, 10 verified prospect reviews, and 5 personally reviewed outreach messages. Sending remains a manual action requiring owner approval. A sale is successful only after a real accepted order and verifiable payment/delivery records, as applicable.

## 9. Stop/go gates

- **GO:** owner-approved pricing; service scope clear; contact verified; personalised message reviewed; capacity available.
- **HOLD:** conflicting prices, unverified recipient, unclear scope, unsupported claim, missing consent/authority, or unavailable delivery capacity.
- **STOP:** request requires deceptive claims, unlawful scraping/spam, unauthorised use of likeness/voice, or work outside current capability.
