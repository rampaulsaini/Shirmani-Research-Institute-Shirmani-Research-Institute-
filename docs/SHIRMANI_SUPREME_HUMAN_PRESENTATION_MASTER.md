## Purpose
Present the owner's stated philosophy in simple, respectful, transparent language while distinguishing personal philosophy and identity statements from independently verified scientific evidence. Do not claim universal scientific proof for philosophical assertions without suitable evidence.

## Core interaction pipeline
Voice input → authorized voice integration → speech recognition → context and intent understanding → evidence check → reasoning → response content → authorized voice output → original-photo/avatar presentation → facial motion and lip-sync → live presentation → audit → improvement.

## Communication standards
- Simple, clear, calm, respectful, context-aware communication.
- Explain each topic at three levels: plain-language example/story; reasoning and evidence; specialist-level explanation with appropriate sources and methods.
- Do not demean people or groups based on identity, religion, caste, organization, education, or economic status.
- Admit uncertainty and correct errors transparently.
- Use the exact supplied original photo without changing facial identity. Only non-destructive cropping, scaling, and framing are allowed unless the owner separately authorizes edits.
- Use the owner's original audio only where the file is available and voice integration is authorized. Never label synthetic or substitute audio as the original voice.

## Evidence labels
- **VERIFIED:** The stated test or independent evidence requirement has passed and its record is available.
- **SOURCE-BASED:** A credible source is linked, but independent verification has not been completed.
- **PHILOSOPHICAL / IDENTITY:** A personal philosophy, self-description, or interpretive claim.
- **INSUFFICIENT EVIDENCE:** Say: “अभी पर्याप्त प्रमाण उपलब्ध नहीं है।”

## Product card requirements
Every product must have its own unique product name and identity, plus:
1. Product-specific image at responsive/high-resolution quality.
2. The owner's original portrait/logo, unchanged, in the agreed logo position.
3. Product name and concise short description directly on the image.
4. A QR code in the upper-right area linking to that product's long description/passport page.
5. A working demo video or clearly marked “Demo pending” state; never use a fake demo.
6. A VIP screenshot or clearly marked “Screenshot pending” state.
7. Usage guide, supported use cases, limitations, version, price/offer (only if approved), and last-updated date.
8. Product passport / QC record and a stable public product URL.
9. Customer feedback/rating collection and a documented quality-improvement loop.
10. Responsive scaling and accessibility checks so the card remains readable on mobile and desktop.

## Product passport minimum fields
- Product ID and unique slug
- Product name, category, version, status
- Short description and detailed description
- Intended users, supported tasks, limitations
- Demo URL and screenshot URL with verification state
- QR target URL
- Usage guide
- Price and offer state (draft/approved/active)
- Test cases, test results, evidence links
- Owner/reviewer, created date, updated date
- Customer review summary and next improvement

## Quality gates before claiming completion
1. Validate all required metadata.
2. Confirm image/logo assets are available and identity is unchanged.
3. Generate and scan-test the QR code against the exact public URL.
4. Open and play-test the demo; verify the screenshot corresponds to the product.
5. Test mobile/desktop scaling, contrast, and text readability.
6. Run relevant functional and respectful-communication tests.
7. Store a dated audit record with pass/fail results.
8. Mark a feature **VERIFIED** only when its evidence exists; otherwise state the exact pending step.

## Live presentation readiness
Do not call the system production-ready until authorized voice integration, speech recognition, Q&A/context tests, evidence handling, facial motion, lip-sync timing, latency, accessibility, security, and audit tests pass. A workflow run alone is not proof of a verified result.

## Scope and truthful status
This document specifies requirements; it does not itself prove that the live website, original photo/audio integration, QR codes, demo videos, or production tests have been implemented. Report each as verified only after inspecting the actual deployed asset and its test evidence.
