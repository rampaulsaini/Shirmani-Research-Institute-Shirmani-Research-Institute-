# ꙰ SHIRMANI Production Mission — Continuation 2026-10-07

## Production-first mandate

The platform must measure progress by concrete public product output, not by workflow count and not by independent verification alone.

## Four-level production pipeline

1. INSTITUTE — discovery, research, product formulation and prioritisation.
2. FACTORY — concrete digital product, module, passport, visual identity, QR and product-specific demo.
3. QC — deterministic product/asset quality gates, packaging state and dispatch controls.
4. SHOWROOM — public customer-facing product page with description, price/offer, demo, usage guide, passport and purchase/inquiry route.

Independent research verification remains a downstream evidence state. It must not block ordinary product production.

## Product asset contract

Every production product should converge toward:

- unique product ID and finalized customer-facing name
- concrete browser-executable or downloadable product asset
- short description visible on the product visual
- long description routed through product-specific QR
- SHIRMANI Heart-View logo/identity treatment
- 3840x2160 16:9 4K-ready visual identity
- VIP screenshot-style asset
- product-specific MP4 demo explaining how to use and where to use it
- interactive usage guide
- Product Passport
- QC code, Gate No. and Dispatch state
- published showroom route
- price and offer metadata
- customer review/rating input
- quality-improvement queue

## Scale

Current concrete production is tracked independently from the 5,000 product scale target and the 150,000 catalogue architecture target.

The 150,000 catalogue is implemented as a sharded architecture so the public interface does not need to load one giant file.

## Customer feedback loop

Customer review/rating -> quality signal -> prioritised production task -> improved product/media/description -> new public version.

Customer feedback is a production-quality input. It is not independent scientific verification.

## External organisations

Official websites and public organisation pages may be mapped into a directory where appropriate. Outreach must remain lawful and must only be reported as completed when an authorised outbound channel actually performs it.

## Continuous operation

The production automission should continue on its scheduled cadence without requiring a new chat message. User absence must not stop repository-local scheduled production workflows.

## Truthful state language

- WORKFLOW RUN = automation activity
- CONCRETE PRODUCT = materialized product asset
- QC PASS = deterministic product/asset gate passed
- PUBLIC = customer-facing route exists
- DISPATCHED = delivery evidence exists
- SOLD/SETTLED = actual order/payment evidence exists
- VERIFIED = independent verification evidence exists

Never collapse these states into one metric.
