# SHIRMANI SUPREME — Execution Board
**Updated:** 2026-10-12  
**Purpose:** Move from approved character specification to demonstrable, tested product increments.

## Current verified repository evidence
- The approved character specification exists at `docs/SHIRMANI_SUPREME_HUMAN_PRESENTATION_SPEC.md`.
- The specification defines original-photo/authorized-voice rules, evidence states, product-specific QR/demo requirements, test gates, and honest readiness labels.

## Execution priorities

### P0 — Asset and deployment inventory
**Deliverable:** dated inventory of the real website, repository entry points, current product catalogue, original photo/voice asset locations, existing QR links, and available demo videos.
**Pass criteria:** each item is linked to an actual repository path or live URL; unavailable assets are marked `NEEDED`; no substitute photo/voice is introduced.

### P1 — One complete reference product
**Deliverable:** one real product page with stable ID/version, short description, approved original photo/logo, identity line, upper-right QR, product passport, usage guide, VIP screenshot, and product-specific MP4 demo.
**Pass criteria:** QR opens the correct live passport on mobile and desktop; demo shows the actual product in operation; all limitations and tested date are visible.

### P2 — Evidence-gated conversation
**Deliverable:** response schema that records one of `VERIFIED`, `SOURCE-BASED`, `PHILOSOPHICAL / IDENTITY`, or `INSUFFICIENT EVIDENCE`.
**Pass criteria:** test cases include supported facts, unsupported claims, ambiguous questions, philosophical statements, and missing-source cases. Missing evidence yields “अभी पर्याप्त प्रमाण उपलब्ध नहीं है।”

### P3 — Authorized voice and presentation integration
**Deliverable:** configured provider connection, authorized voice asset, sample Q&A, rendered output, and sync report.
**Pass criteria:** provider permission and asset authorization are recorded; actual speech, face, gaze/expression, lip-sync, and timing are inspected. No live-ready label until the end-to-end gate passes.

### P4 — Feedback and quality loop
**Deliverable:** feedback form tied to product ID/version, triage states, reproducible defect record, and release notes.
**Pass criteria:** a submitted test review can be traced to a decision and, where accepted, a versioned improvement. Do not fabricate customer reviews.

### P5 — Real-income service workflow
**Deliverable:** enquiry page/form for Hindi/English writing, research summaries, and website/blog content; scope/price/deadline/payment confirmation before work.
**Pass criteria:** enquiry submission works; no work is represented as booked until the customer confirms the written terms; revenue is reported only from actual paid transactions.

## Release status definitions
- `SPECIFIED`: documented requirement.
- `IMPLEMENTED`: code or asset is present and inspected.
- `TESTED`: named test ran with a recorded result.
- `VERIFIED`: acceptance criteria passed with evidence.
- `LIVE`: intended production URL was opened and checked.
- `NEEDED/BLOCKED`: asset, permission, credential, provider, or test is unavailable.

## Metrics to report at each checkpoint
| Metric | Measurement |
|---|---|
| Reference-product completeness | passed required product artifacts / total required artifacts |
| QR validity | correct live destinations / QR codes tested |
| Demo coverage | products with actual product-specific demos / published products |
| Evidence-gate pass rate | passing evidence tests / evidence tests run |
| Presentation end-to-end pass rate | passing critical gates / critical gates run |
| Enquiry workflow | successful test submissions / test submissions attempted |
| Paid income | confirmed payments only; otherwise ₹0 confirmed in this report |
| Outreach | successful authorized sends with provider evidence; never inferred from drafts |

## Immediate blocker policy
Do not claim completion where the actual asset, credential, live endpoint, test result, or payment evidence has not been inspected. Keep the approved character specification unchanged unless a real defect requires a traceable edit. Prefer one complete reference product over a large catalogue of unverified placeholders.
