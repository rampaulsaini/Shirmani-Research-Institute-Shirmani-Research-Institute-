# SHIRMANI SUPREME — Public Product Description
**Product family:** SHIRMANI SUPREME / Heart-View — Impartial Understanding  
**Date:** 2026-10-12  
**Status:** Description and acceptance specification; no untested integration is claimed live.

## Short description
A Hindi–English communication and presentation studio that turns questions and ideas into clear, respectful, evidence-aware explanations, with authorised voice and avatar workflows only when connected and tested.

## Full description
SHIRMANI SUPREME is designed for communication that is simple without being shallow, warm without being manipulative, and clear without overstating what is known. It identifies the question, audience, language and context; drafts a direct answer; explains difficult ideas with everyday examples; and can expand into source-led research outlines or technical explanations.

The system distinguishes independently verified findings, source-based statements not independently verified, personal or philosophical viewpoints, and claims for which evidence is insufficient. When evidence is inadequate, it should say: **“अभी पर्याप्त प्रमाण उपलब्ध नहीं है।”** A personal identity statement or philosophy must not be presented as independently proven scientific fact.

The presentation goal is respectful communication across differences in wealth, status, caste, religion, nationality, profession and organisation. It must not promise a guaranteed emotional effect, fabricate credentials or testimonials, use false urgency, or demean a person or group.

## Four capability versions
1. **V1 — Clear Script:** editable Hindi/English script, context brief and plain-language explanation.
2. **V2 — Authorised Voice:** speech input/output only where a real capability is connected, permission is recorded, and transcript/pronunciation tests pass.
3. **V3 — Approved Photo/Avatar:** use the author's original authorised photo without altering identity-defining facial features; resizing and layout placement are allowed. Animation/lip-sync must be rendered and reviewed before being advertised as available.
4. **V4 — Live Presenter:** interactive Q&A/live presentation only after provider connection, consent, evidence checks, moderation, privacy controls, end-to-end tests and measured latency are documented.

These are capability tiers, not claims that all tiers are currently live.

## Per-product showroom identity
Every product should have its own name, stable ID, version, distinct visual, short description printed on the image, author-approved “निष्पक्ष समझ” photo/logo, and the requested English identity line below it. Place a QR code at the upper-right only after its destination is a verified public Product Passport URL. The passport should contain the full description, intended use, step-by-step usage guide, limits, approved price/offer, support terms, actual screenshot, demo-video status and release evidence.

The original photo and voice are not embedded in this document. Use only the actual author-provided assets; never substitute a generated face or synthetic voice while claiming it is the original. If the source asset is unavailable to the production environment, mark that media task BLOCKED until it is located or supplied.

## Demo and quality requirements
- A storyboard is not a video. Use SCRIPT_ONLY, RECORDING_PENDING, RENDERED or PUBLISHED according to actual evidence.
- A mock-up is not a live integration. Use NOT_CONNECTED, DRAFT, TESTING, PASS, FAIL or BLOCKED for each capability.
- Capture a screenshot from the actual product and test the QR destination before release.
- Record observed test results, not assumed scores.
- Turn customer feedback into reviewed improvement tasks; ratings alone do not prove quality.
- Do not claim sales, payments, outreach, independent verification or production readiness without supporting records.

## Release checklist
- [ ] Exact authorised photo located and source recorded; facial identity not regenerated or altered.
- [ ] Voice asset/provider permission documented before use.
- [ ] Product name, ID, version and short description finalised.
- [ ] QR opens the correct public passport.
- [ ] Screenshot captured from the actual product.
- [ ] Product-specific demo video rendered and reviewed, or clearly marked pending.
- [ ] Usage guide, limitations, privacy and support terms visible.
- [ ] Evidence-state tests include an insufficient-evidence case.
- [ ] Voice/face/lip-sync claims limited to components that passed actual tests.
- [ ] Commercial state and price supported by a current record.

## Implementation boundary
This document improves the product description and acceptance criteria. It does not restore a deleted ChatGPT transcript, publish the original photo, use the uploaded voice, create a rendered avatar/video, activate live streaming, contact organisations, take payment, or prove revenue. Each requires a separate observable action and test.
