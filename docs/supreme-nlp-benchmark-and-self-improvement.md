# SHIRMANI Supreme NLP Benchmark & Controlled Self-Improvement

## Purpose

Extend the existing Supreme NLP / Automission stack from operational health into reproducible benchmark evidence and controlled improvement proposals.

## Evidence pipeline

Benchmark definition → dataset fingerprint → baseline → candidate → metric → delta → regression analysis → uncertainty → provenance → review → VERIFIED/BLOCKED.

## Non-negotiable boundaries

- Workflow success is not model accuracy.
- Confidence is not truth.
- A single benchmark is not universal capability.
- A biological, plant, environmental or non-living signal is not by itself proof of subjective feeling, consciousness or intention.
- No agent may silently promote an unverified result to VERIFIED.
- No agent may deploy self-modifying production code without the repository's required tests, security checks and human authorization.

## Controlled self-improvement

Automission may detect a measurable regression or improvement opportunity, create a machine-readable improvement proposal, identify affected benchmark/task/model components, calculate the observed delta, and require independent review before promotion.

Automission may not fabricate benchmark values, replace missing evidence with confidence, rewrite governance controls to bypass a blocker, publish a VERIFIED claim without the required verification state, or perform irreversible/financial actions without authorization.

## Minimum benchmark record

Each record contains task, population scope, dataset fingerprint, model/version, metric, baseline, candidate result, delta, uncertainty, provenance, limitations and verification state.

## Improvement criterion

For higher-is-better metrics: delta = candidate - baseline.

For lower-is-better metrics: delta = baseline - candidate.

A positive delta alone is insufficient. The task definition, dataset protocol and evaluation procedure must remain comparable, and regressions on protected slices must be checked.

## Five-minute role

Every five-minute cycle may perform deterministic benchmark-contract validation and inspect committed benchmark records. Expensive training and external data acquisition remain separately budgeted.

## Status model

REGISTERED → UNVERIFIED → REVIEW → VERIFIED

BLOCKED is fail-closed until its blocker is resolved.

PROPOSED_IMPROVEMENT is an action proposal, not verification.

VERIFIED requires independent verification evidence.

UNVERIFIED is the default for newly generated evidence.
