# SHIRMANI NISHPAKSH SUPREME NLP / AUTOMISSION

## Purpose
A fail-closed, evidence-first architecture for continuous AI-agent, ML and NLP improvement.

## Core rule
The system must distinguish:
1. user-authored/framework propositions;
2. observations and measured signals;
3. model inferences;
4. externally supported claims;
5. independently verified claims.

No model output may silently upgrade one category into another.

## Heart-View / Nishpaksh contract
- Preserve user-authored source text as immutable source material.
- Treat framework propositions as propositions unless independently supported.
- Never fabricate evidence, certainty, emotion, consciousness, intent or subjective experience.
- For living organisms, plants, machines or inanimate systems, translate only observable/measurable signals into plain language and explicitly report uncertainty.
- A signal-to-language output is an interpretation, not proof of a subjective feeling.
- Conflicting evidence must remain visible.
- Every consequential action is gated.
- Irreversible, financial, publication and verification-promotion actions require their configured authorization boundary.

## Continuous loop
OBSERVE -> NORMALIZE -> UNDERSTAND -> REASON -> EVIDENCE -> COUNTER-CHECK -> VERIFY -> AUDIT -> IMPROVE -> PUBLISH

## NLP stack
- multilingual tokenization and normalization
- semantic parsing and intent/context extraction
- temporal and causal context
- multimodal signal adapters
- uncertainty/calibration layer
- knowledge graph / provenance graph
- contradiction and counter-evidence detector
- plain-language explanation layer
- human-review escalation

## Accuracy contract
Do not use an unmeasured "supreme accuracy" claim. Measure:
- task accuracy / F1 / exact match where applicable
- calibration error
- false-positive / false-negative rates
- contradiction rate
- provenance completeness
- independent-verification rate
- regression rate
- reproducibility
- latency and resource cost

## Signal-to-language safety boundary
For sensor, plant, biological or environmental data:
signal -> preprocessing -> feature extraction -> model -> context -> uncertainty -> plain-language report

Required report fields:
signal_observed
interpretation
alternative_interpretations
confidence
evidence
limitations
verification_status

## Automission safety
The Automission loop may propose improvements automatically. It may not silently:
- promote an unverified claim to verified;
- alter immutable source records;
- publish consequential claims without passing gates;
- execute irreversible or financial actions without authorization;
- expose secrets.

## Definition of done
A change is accepted only when deterministic QC, security checks, provenance checks, regression tests and the applicable verification gate pass.
