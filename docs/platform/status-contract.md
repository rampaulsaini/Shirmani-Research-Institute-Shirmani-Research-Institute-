# Public Status Contract

The platform exposes status as evidence, not as a promise.

Each feature should publish: feature ID; implementation status; deployment status; last successful check; owning workflow/service; source commit; known blockers; human-review requirement; evidence links.

## Required distinction

A green workflow means the workflow completed according to its test contract. It does not by itself mean that a philosophical, scientific, social, economic, legal, or governance claim has been independently verified.

## Fail-closed verification

Independent verification remains zero until a qualifying independent review decision is recorded for the applicable claim and its evidence contract is satisfied.

## High-impact actions

Money movement, access revocation, dispute outcomes, legal-impacting actions, publication of independent verification, and irreversible repository changes must have an explicit authorization gate and an auditable event.

## Public metrics

Show separate metrics for research preparation, evidence/traceability, automation health, public deployment, service readiness, revenue readiness, and independent verification.

Do not combine these into a single project score.
