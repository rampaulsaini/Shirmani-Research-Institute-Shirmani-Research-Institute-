# Yatharth Public Platform — Capability Status Contract

This registry is the public-facing source of truth for distinguishing an interface entry point from a deployed capability.

## Status vocabulary

- PLANNED — defined as a target capability; no deployment evidence yet.
- ARCHITECTURE — design/contract exists; implementation may be incomplete.
- DEVELOPMENT — implementation work is active.
- TESTING — implementation exists and is undergoing tests.
- LIVE — public deployment evidence exists.
- LIMITED_LIVE — only a bounded subset is deployed.
- HUMAN_REVIEW_REQUIRED — high-impact actions require human approval/appeal.
- INDEPENDENTLY_VERIFIED — independent review/evidence contract has been satisfied.

Never infer LIVE, VERIFIED, or financial/legal operation from a GitHub workflow success alone.

## Autonomous operating contract

Routine operations may be automated through AI agents, ML/NLP pipelines and Automission. High-impact account, financial, dispute, safety, justice and independent-verification decisions require bounded autonomy, auditability, human oversight and an appeal path.

## Mission metrics

Track separately:

1. user satisfaction and successful task completion;
2. safety, abuse and fraud rates;
3. content quality and evidence traceability;
4. automation reliability;
5. service availability;
6. nature/humanity outcome indicators;
7. independent verification progress.

Do not collapse these into a single “success percentage”.

## Human-first basic-needs principle

The platform may research and support access to food, clothing, shelter, healthcare and education. Any promise of universally free provision must be backed by a lawful, funded and operational delivery model before being presented as a live service.

## Future scale

The 850-crore-user figure is retained as a long-term aspirational scale target, not as a current user count or guaranteed outcome.
