# Yatharth Autonomous Operating Architecture

## Scope

This document defines how AI agents, ML, NLP and Automission can operate the platform without collapsing safety, justice, verification, or human agency into one automated decision-maker.

## Decision classes

### Class 1 — Routine automation
Examples: indexing, formatting, translation, metadata enrichment, duplicate detection and routine notifications.

These may be fully automated subject to monitoring.

### Class 2 — Reversible user-impact decisions
Examples: recommendations, ranking, temporary visibility changes and marketplace matching.

These require explainability, monitoring and user controls.

### Class 3 — High-impact decisions
Examples: permanent account sanctions, major financial actions, legal/justice outcomes, sensitive eligibility decisions and independent scientific verification.

These require human review, appeal, or an explicitly independent process.

## Automission contract

Every autonomous workflow should record:

Input → Agent/Model → Rules/Policy → Action → Evidence/Trace → Outcome → Rollback/Appeal path.

## ML/NLP principles

Models must be evaluated for accuracy, drift, bias, false positives/negatives, multilingual performance and adversarial behavior. Model output must not be treated as independent verification merely because an AI system produced it.

## Environmental objective

Platform-level optimization should include measurable goals for energy/resource efficiency, environmental information, conservation projects and responsible digital infrastructure.

## Human agency

The system should increase people's ability to create, learn, work, participate and make informed decisions. It should not silently replace human choice in high-impact domains.

## Fail-closed rule

When required evidence, authorization, safety checks, or verification inputs are missing, the automated action must stop or downgrade to review rather than invent certainty.

## Public transparency

Public dashboards should distinguish:
- live product features;
- automated operations;
- research status;
- independent verification;
- human-reviewed decisions;
- incidents and remediation.

This separation prevents automation success from being mistaken for scientific, legal, or social validation.
