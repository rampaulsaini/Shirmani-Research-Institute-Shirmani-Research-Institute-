# AI Agent, ML, NLP and Automission Autonomy Contract

## Objective
Provide coordinated automation for the Yatharth public ecosystem without representing planned capabilities as already deployed.

## Agent layers
### L1 — Intake
Receives user content, listings, research material, reports, jobs, services and support requests.

### L2 — NLP Understanding
Extracts language, topics, entities, claims, intent, language and structured metadata.

### L3 — Safety and Integrity
Detects spam, abuse, manipulation, duplicates, suspicious transactions and policy risks.

### L4 — Knowledge and Recommendation
Builds semantic links and recommendations with appropriate explanations.

### L5 — Marketplace and Service Matching
Matches buyers, sellers, learners, employers, freelancers, creators and researchers.

### L6 — Research and Evidence
Maps claims to sources, counter-evidence, tests and review status.

### L7 — Operations
Runs queues, health checks, retries, observability, incident response and workflow coordination.

### L8 — Federation
Coordinates repositories/services through authenticated least-privilege interfaces.

### L9 — Public Presentation
Publishes dashboards, status, multilingual content and user-facing results.

### L10 — Continuous Audit
Checks contracts, provenance, safety, drift, failures and anomalous behavior.

## ML/NLP requirements
For each production model record model/version, input scope, training or retrieval source where available, evaluation set, limitations, uncertainty where meaningful, human-review requirements and rollback path.

## Automission rules
1. Every autonomous action has explicit scope.
2. Credentials use least privilege.
3. Secrets never enter prompts, logs, issues or public content.
4. Financial and high-impact actions have limits and escalation.
5. Account sanctions have appeal mechanisms.
6. Verification cannot be granted merely because an AI workflow succeeds.
7. Agents fail closed when evidence or authorization is missing.
8. Material actions have auditable event records.
9. Model drift and automation failures trigger monitoring and recovery.
10. Human override remains available for high-impact operations.

## Autonomy maturity
A component is not called fully autonomous until it demonstrates:
SPECIFICATION → IMPLEMENTATION → TESTS → FAILURE RECOVERY → SECURITY REVIEW → OBSERVABILITY → PILOT → PRODUCTION EVIDENCE.

Existing GitHub Actions demonstrate substantial automation and continuous checks. They do not, by themselves, prove that the complete public social, marketplace, education, economy, justice or AI/ML/NLP ecosystem is production-live.
