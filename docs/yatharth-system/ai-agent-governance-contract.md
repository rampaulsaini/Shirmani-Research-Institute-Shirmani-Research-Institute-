# AI Agent, ML, NLP & Automission Governance Contract

## Objective
Define how autonomous agents can operate the Yatharth public platform without confusing automation with truth, authority, justice, or independent verification.

## Agent layers
1. Intake Agent — receives user/content events.
2. NLP Agent — extracts language, topics, entities and claims.
3. Classification Agent — routes content to the correct module.
4. Evidence Agent — locates and records evidence where permitted.
5. Safety Agent — detects abuse, fraud, privacy and security risks.
6. Recommendation Agent — personalizes discovery without coercive engagement.
7. Marketplace Agent — assists matching, listings and transactions.
8. Education Agent — assists learning and assessment.
9. Creative Agent — assists music, media and digital creation.
10. Research Agent — builds research packets and comparison maps.
11. Audit Agent — checks traceability and policy contracts.
12. Verification Gate — blocks VERIFIED status without the defined evidence contract.
13. Federation Agent — coordinates approved repositories/services.
14. Recovery Agent — detects failures and initiates bounded recovery.
15. Public Presentation Agent — publishes only approved public artifacts.

## ML/NLP principles
Models must record model/version provenance where practical, distinguish generated text from source material, expose uncertainty where material, and avoid treating semantic similarity as factual proof.

## Automission rules
- Least privilege.
- Explicit action scopes.
- Idempotent operations where possible.
- Rate limits and resource budgets.
- Immutable audit trails for high-impact actions.
- Fail closed for verification and high-impact governance.
- Human escalation for disputes, account termination, major financial actions and other high-impact decisions.
- No hidden modification of canonical author source.
- No secret/token disclosure.
- No autonomous claim that an unverified proposition is scientifically established.

## Engagement principle
Optimize for user value, safety, satisfaction and meaningful participation—not addictive or manipulative engagement.

## Public transparency
The public status interface should distinguish:
BUILT / TESTED / LIVE / AUTOMATED / INDEPENDENTLY REVIEWED / VERIFIED.

A workflow success is evidence that the workflow executed successfully; it is not evidence that every underlying claim is true.
