## Account capabilities
A registered user may progressively receive:
- profile
- publishing
- follows/connections
- comments and moderation controls
- creator page
- product listing
- service listing
- course publishing
- portfolio
- orders
- earnings dashboard
- support tickets
- privacy controls
- account export and deletion controls

Actual availability depends on implementation, authentication, payments, moderation and applicable law.

## Platform flywheel

**Create → Share → Discover → Learn → Collaborate → Buy/Sell → Deliver → Review → Improve**

The objective is user value and satisfaction, not maximizing time spent through manipulative design.

## Trust layer
Every important public claim should be classifiable as:
- Author Source
- Normalized Claim
- Evidence Mapped
- Comparative Review
- Independent Review
- Verified
- Partially Supported
- Inconclusive
- Not Verified

## Scale objective
The project may retain **8.5 billion people** as a long-term aspirational reach target. It is not a current user count, forecast or guarantee.

## Implementation rule
Public interface claims must correspond to a machine-readable feature registry and a tested implementation state. Architecture documents do not by themselves activate the corresponding product feature.
