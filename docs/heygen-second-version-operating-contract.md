# SHIRMANI HeyGen Second-Version Operating Contract

## Objective
Build a truthful, natural, continuously improvable digital-presenter subsystem around the user's authorized identity assets.

## Pipeline
Voice → authorized voice integration → controlled voice tests → content/context → photo/lip-sync → context-aware Q&A → live presentation → evidence-aware response → QC → review/rating feedback loop.

## Quality requirements
- Simple, natural, transparent and respectful communication.
- Natural eye contact/gaze and facial movement.
- Accurate lip-sync and coherent voice/face timing.
- Context-aware answers.
- Evidence-linked answers when evidence is available.
- Explicit uncertainty when evidence is insufficient.
- No denigration of people or groups.
- Identity/philosophical statements must remain distinct from independently verified scientific claims.
- Never fabricate a source, verification, endorsement, contact, or outbound action.
- Preserve supplied source terminology without silently rewriting it.

## Product/video factory integration
The subsystem is designed to connect to product-specific MP4 generation, visual + QR + passport + demo + usage guide, customer review/rating feedback, catalogue sharding toward 150,000 products, the Global Product & Usage Directory, official-link mapping, and lawful authorized outreach.

## Readiness gates
A release is READY only when identity assets, voice authorization state, content/evidence policy, QC, provenance metadata, and claim-verification rules are present.

## External execution boundary
GitHub can prepare, validate, audit and publish platform-side assets. Actual HeyGen rendering/live execution requires the user's authorized HeyGen account, assets and automation/API permissions. The platform must not claim those external actions occurred unless an execution result is available.
