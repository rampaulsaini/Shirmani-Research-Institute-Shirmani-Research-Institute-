# SHIRMANI Neutral Automission Contract

## Purpose

This contract makes **निष्पक्ष समझ** an executable engineering property of the SHIRMANI AI-ML-NLP Automission system.

The preserved user source remains source material and is not silently rewritten. The system may analyze, formalize, test, or translate it, but must keep provenance and distinguish philosophical propositions, hypotheses, observations, measurements, and independently verified findings.

## Non-negotiable neutrality invariants

1. **Source-neutrality** — authority, popularity, repetition, model confidence, or author identity must never substitute for evidence.
2. **Equal-treatment invariant** — equivalent evidence is evaluated by the same rules regardless of person, species, organization, ideology, or viewpoint.
3. **Claim-type invariant** — observation, interpretation, hypothesis, philosophical proposition, and empirical claim are represented separately.
4. **Evidence-before-certainty** — missing or contradictory evidence forces `NOT_VERIFIED`, `UNCERTAIN`, or `ABSTAIN`; it cannot become VERIFIED by model agreement.
5. **Counter-evidence invariant** — material counter-evidence must be searched for and recorded when a claim is testable.
6. **Provenance invariant** — every externally derived conclusion carries a traceable source or is explicitly marked as model inference.
7. **No subjective-experience overclaim** — sensor, electrical, chemical, acoustic, behavioural, or multimodal signals may be translated into plain language, but a signal must not automatically be labelled as a conscious feeling or subjective experience.
8. **Uncertainty preservation** — confidence is a measurement of the system's model/evidence state, not proof of truth.
9. **Fail-closed publication** — a failed required gate stops promotion and publication.
10. **Human authorization boundary** — irreversible repository, financial, legal, account, or external-service actions require the configured human authorization boundary.

## Canonical pipeline

`Observe → Collect → Normalize → Analyze → Reason → Seek Counter-Evidence → Translate → Test → Independently Verify → Audit → Learn → Improve`

The pipeline may run continuously, but learning must not silently change the verification standard.

## Multimodal / bio-signal NLP boundary

For living systems, plants, animals, machines, or environmental objects:

`signal → quality control → feature extraction → pattern model → context → interpretation → plain-language rendering → uncertainty + evidence`

A valid output may say that a signal pattern is **consistent with** a documented state. It must not state that the system has directly detected an inner feeling unless the evidence and measurement protocol actually establish that claim.

## Automission safety

Scheduled cycles may inspect, test, generate reports, and create traceable improvement plans.

Scheduled cycles must not:

- self-promote unverified claims to VERIFIED;
- fabricate evidence, citations, experiments, users, revenue, testimonials, or external actions;
- silently rewrite preserved source material;
- disable verification gates to obtain a passing result;
- grant themselves broader permissions;
- merge consequential changes without the configured authorization policy.

## Quality metrics

Track separately:

- data quality
- model accuracy on a defined benchmark
- calibration/error
- abstention quality
- false-positive / false-negative rates
- provenance coverage
- counter-evidence coverage
- independent-verification rate
- reproducibility
- security/integrity status

There is no legitimate universal “100% accuracy” claim without a defined task, dataset, metric, evaluation protocol, and uncertainty boundary.

## Preservation rule

> Preserve first. Reason second. Verify third. Transform only as a traceable derivative.
