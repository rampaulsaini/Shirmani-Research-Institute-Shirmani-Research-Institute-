# Implementation Backlog

## Phase A — public foundation
- Connect the source library to a searchable public index.
- Expose claim IDs, lifecycle status, evidence links and counter-evidence.
- Publish a machine-readable verification status contract.
- Add public system-health and automation-health pages.
- Keep independent verification claim-specific and fail-closed.

## Phase B — AI/ML/NLP
- Implement source segmentation and claim extraction.
- Attach provenance to every extracted statement.
- Add semantic clustering and duplicate detection.
- Add evidence retrieval and contradiction/counter-evidence queues.
- Add model evaluation datasets and regression tests.
- Keep model output labeled as generated/assisted until independently reviewed where required.

## Phase C — Automission
- L1 intake → L2 claim → L3 evidence → L4 comparison → L5 audit.
- L6 verification gate must reject unsupported transitions.
- L7 federation handles bounded cross-repository events.
- L8 public presentation publishes only contract-valid records.
- Add retry, dead-letter, idempotency and audit-trail handling.

## Acceptance rule

A feature is not marked live merely because its documentation, workflow, mockup, or generated artifact exists. Live requires a deployed implementation and passing contract checks for that surface.
