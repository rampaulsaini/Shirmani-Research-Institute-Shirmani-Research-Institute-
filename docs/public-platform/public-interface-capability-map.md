## Account and identity
Every eligible user account may have:
- profile and public identity
- privacy and consent controls
- content library
- creator mode
- seller/service-provider mode
- learner mode
- researcher/contributor mode
- purchase/order history
- earnings and payout records where supported
- reputation and review history
- accessibility and language preferences
- data export and account recovery

Account roles are composable rather than mutually exclusive.

## Publish and create
Users may, subject to applicable rules and feature availability:
- publish text, images, audio, video and other supported media
- create pages/channels
- create courses and learning material
- publish research and evidence-linked material
- offer services
- list eligible digital products
- create music/media projects
- collaborate with other creators

Publication status must be distinguishable from verification status.

## Commerce and freelancing
The public interface should support a complete lifecycle:
Discover → View → Compare → Purchase/Contract → Deliver → Review → Resolve issue → Complete.

Required supporting contracts include:
- product/service metadata
- pricing and currency display
- order state
- delivery state
- refund/cancellation policy
- seller/provider identity state
- customer support
- review/reputation
- fraud and abuse signals
- jurisdiction-aware payment integration

No financial capability is considered LIVE until its backend, security, legal, payment and reconciliation controls are implemented and tested.

## Education
Public education features include:
- courses
- lessons
- learning paths
- assessments
- progress
- certificates where legitimately issued
- creator/instructor profiles
- accessible and multilingual delivery

## Research and verification
Public research must expose provenance and status:
Author Source → Normalized Claim → Evidence → Counter-Evidence → Test → Independent Review → Status.

Automated generation never substitutes for independent verification.

## AI-native experience
AI may assist with:
- search and discovery
- translation
- summarization
- recommendations
- creator assistance
- learning assistance
- research navigation
- customer support
- marketplace matching
- moderation signals
- accessibility

Users should be able to understand when an interaction is AI-assisted and access escalation/review paths where appropriate.

## Public-value dashboard
Measure and expose, where data quality permits:
- user satisfaction
- successful task completion
- creator outcomes
- learning outcomes
- service reliability
- accessibility
- safety incidents
- dispute resolution metrics
- research traceability
- environmental initiatives and evidence

Avoid optimizing solely for time spent.

## Global accessibility
Design targets:
- mobile-first
- low-bandwidth modes
- multilingual interface
- accessible media
- progressive loading
- resilient operation
- exportable user data

## Feature-state rule
A public button, menu item or page must map to a machine-readable capability state. Documentation alone cannot mark a feature LIVE.
