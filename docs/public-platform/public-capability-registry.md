## Account model
A registered user may, subject to applicable law and platform rules:
- create a profile;
- publish and share permitted content;
- create communities;
- offer services;
- list eligible digital products;
- sell eligible products/services where payment and compliance infrastructure exists;
- learn, teach or create courses;
- participate in research and public-interest projects;
- receive ratings, feedback and support.

## Capability lifecycle
PLANNED → ARCHITECTURE → IMPLEMENTED → TESTED → BETA → LIVE → MONITORED

A capability must not be labelled LIVE merely because documentation, a workflow or a successful CI run exists.

## Public status
Every module exposes:
- status;
- last validation;
- limitations;
- data/privacy boundary;
- human-review boundary;
- support/appeal path.

## Non-negotiable boundary
The platform may pursue high automation, but AI/ML/NLP/Automission does not become an unaccountable sovereign authority. High-impact access, financial, legal, safety, rights and dispute decisions require defined controls and appeal mechanisms.
