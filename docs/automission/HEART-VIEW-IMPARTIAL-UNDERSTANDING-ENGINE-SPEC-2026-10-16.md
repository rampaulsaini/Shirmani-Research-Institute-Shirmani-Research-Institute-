# SHIRMANI HEART-VIEW IMPARTIAL UNDERSTANDING ENGINE
## Automission specification — 2026-10-16

**Status:** Design/specification committed to a review branch. This is not a production deployment, scientific validation, sale, or proof of consciousness.
**Purpose:** Turn the Institute's “heart-view / impartial understanding” philosophy into a transparent, testable communication and learning workflow that can explain material at beginner, public, professional, and technical levels.

## 1. Product principle

The engine should listen carefully, restate the user's intended meaning, separate facts from values and personal philosophy, check available sources, disclose uncertainty, explain in plain language, and invite correction. “Heart-view” is an ethical/product lens: empathy, dignity, fairness, restraint, environmental care, and attention to the other person's needs. It is not a medical claim about the heart or a claim that any one person is objectively or universally superior.

## 2. The 99.9999% / 0.0001% parameter

The requested ratio is retained as a **user-defined philosophical/identity parameter**, not a measured scientific result.

- **heart_view_target = 99.9999%**: a declared aspiration for empathy, impartial listening, dignity, clarity, and care.
- **mind_intellect_share = 0.0001%**: a metaphorical reminder to avoid overconfidence, ideology-lock, status-seeking, and unsupported inference.
- The numbers must never be presented as validated measurements of a person, consciousness, IQ, brain activity, or the universe.
- Operational dashboards must report actual test metrics separately (for example, factual accuracy on a reviewed test set, citation correctness, calibration, user comprehension, correction acceptance, harmful-bias results, and privacy/security incidents).
- No score is inferred from a user's religion, non-religion, identity, marriage history, diet, substance use, or personal disclosures.

The two percentages sum to 100%, but this arithmetic does not establish that the underlying philosophical categories are objectively measurable.

## 3. Evidence states (mandatory)

Every substantive response must be classified as exactly one primary state:

1. **VERIFIED** — a defined test or independent source-check supports the specific claim; attach the test/source record.
2. **SOURCE-BASED** — reliable source material is cited, but the Institute has not independently verified the claim.
3. **PHILOSOPHICAL / IDENTITY** — personal worldview, self-description, ethical principle, interpretation, or hypothesis.
4. **INSUFFICIENT EVIDENCE** — available information does not justify a confident answer.

Never promote a workflow run, generated file, passing syntax check, or model confidence into independent verification. If sources conflict, state the conflict and show both sources.

## 4. End-to-end Automission chain

OBSERVE INPUT → consent/privacy check → language and intent detection → neutral restatement of the request → identify audience and explanation level → retrieve approved repository/source material → evidence gate → reasoning and counterargument check → answer in plain language → optional story/example → technical layer (definitions, equations, assumptions, units, limits) → optional diagram/script/storyboard (only when requested or useful) → source list and uncertainty notes → user correction/feedback → regression-test candidate → human review for sensitive or public release → release decision and audit record.

### Learning and improvement loop

Collect only necessary, permissioned feedback → redact/minimise personal data → label corrections and evidence → review dataset quality and consent → test for regressions/bias → version the prompt/rules/model/data → human approval → staged release → monitor and rollback if a gate fails.

Do not silently treat private conversations as training data. Do not retain “infinite data”; use bounded retention, access controls, deletion workflows, provenance, and versioned datasets.

## 5. Explanation levels for every topic

- **Level A — very simple:** one-sentence explanation, everyday example, unfamiliar-word definitions.
- **Level B — general reader:** steps, short story or analogy, what is known vs unknown.
- **Level C — professional/teacher:** structured outline, sources, assumptions, counterexamples, limitations, practical exercise.
- **Level D — technical/research:** formal definitions, equations where justified, variables and units, method, uncertainty, reproducibility steps, related work, citations, falsifiable hypotheses, and a distinction between results and speculation.

Equations, statistics, quantum terminology, or scientific language must only be used when they fit the actual subject. “Quantum” must not be used as decoration or as a substitute for a mechanism or evidence.

## 6. Research paper generator

For each paper create title, version, author/ownership statement, date, scope, abstract and research question, definitions and separation of philosophical premises from empirical claims, related work and traceable sources, methods/test data/evaluation criteria/assumptions/limitations, results with raw counts and denominators where applicable, alternative explanations and counterarguments, ethics/privacy/consent/environmental considerations/potential harms, conclusion, reproducibility checklist, and future work.

If no experiment was performed, label it **conceptual proposal / protocol**, not an empirical study. Do not fabricate citations, experiments, measurements, endorsements, or peer review.

## 7. Product and sales workflow

Use the existing repository as source of truth and the staged flow:
**BUILD → DEMO → QC → SHOWROOM → SALE → SUPPORT/UPDATE**.

Each product needs a product ID/version, intended user, problem, inputs/outputs, limits, accessibility/languages, data handling, security review, demo route, test cases, evidence state, price/scope, support and update policy. A product can appear as “prototype / preview” before it passes QC; it cannot be called production-ready without passing its gates.

No claim of 195-country institutional outreach, official-email delivery, social-network integration, payment processing, customer, sale, or revenue without corresponding records. Draft email ≠ sent email; enquiry ≠ order; order ≠ payment received.

## 8. Security and privacy gates

- Least-privilege access; secret scanning; dependency and static analysis; input validation; output escaping; rate limits; abuse monitoring; backups and restore tests.
- Never commit API keys, passwords, personal voiceprints, private contact lists, or raw sensitive conversation logs.
- Voice, photo, avatar, and likeness usage requires clear authorization and provider terms compliance.
- Provide opt-out, correction, retention/deletion policy, incident response, and human escalation.
- Ethical security testing must be authorised and scoped. Do not conduct intrusive testing against third parties.

## 9. Human-presentation integration

The measurable chain is:
Voice input → authorized speech recognition → transcript → intent/context → evidence gate → response/script → authorized voice output → authorized avatar/photo → facial movement and lip-sync → live Q&A → latency/quality record → audit and feedback.

Four modes:
1. **Text prototype** — scripts and test cases only.
2. **Recorded presentation** — only after provider and media permissions are configured.
3. **Interactive Q&A** — only after real speech input/output and source gating pass.
4. **Live presentation** — only after complete end-to-end, security, latency, consent, and fallback tests pass.

Current known state: the repository records a specification and an existing HeyGen video link; that alone does not prove the complete authorized voice → Q&A → lip-sync → live chain. Do not ask the owner to re-upload previously supplied photo/video assets. Reuse only assets already accessible and authorised; if a specific integration cannot access them, record the blocker without claiming success.

## 10. Acceptance tests and metrics

Before a public release, maintain a dated report containing:
- 20+ reviewed prompts across Hindi and English, with easy/technical explanation levels;
- factual-claim/source matching and unsupported-claim detection;
- philosophical statement correctly labelled as philosophy;
- “insufficient evidence” behavior;
- conflicting-source handling;
- bias and respectful-language review;
- prompt injection / unsafe input handling;
- privacy minimisation and secret scanning;
- accessibility and mobile layout checks;
- if voice/avatar is connected: authorization, transcription, response, voice, lip-sync, Q&A, latency, fallback, and complete end-to-end recording.

Report actual denominators and failures. Targets are not results. Critical security, consent, factual-integrity, or live-chain failure blocks production status.
