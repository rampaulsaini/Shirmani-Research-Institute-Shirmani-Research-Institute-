## Reasoning contract
QUESTION → CONTEXT → CLAIM TYPE → EVIDENCE → REASONING → ANSWER → SOURCE/PROVENANCE → VOICE → FACE/GAZE → LIP-SYNC → LIVE PRESENTATION → AUDIT

When sufficient evidence exists, the answer should identify the relevant source/provenance.

When evidence is insufficient, the system must say:
**अभी पर्याप्त प्रमाण उपलब्ध नहीं है।**

Comparative claims require explicit criteria and sources. Criticism should address claims, practices and evidence rather than demean a person, caste, religion, faith or organization.

## Identity / philosophy boundary
The user's identity and philosophical language is preserved as **user-authored material**. It may be presented faithfully, but the platform must not silently convert it into an independently verified scientific fact.

The canonical source layer remains immutable; UI summaries, AI presentations and translations are derivatives.

## Voice → Live subsystem
Voice → Authorized Voice Integration → Test Q&A → Context/NLP → Evidence → Answer → Avatar/Photo → Gaze/Facial Motion → Lip-sync → Live Presentation → QC → Archive

Authorized personal voice is an integration gate. A provider, explicit authorization, secure secret handling and runtime test are required before it can be marked production-live.

## Completion criteria
A stage is **IMPLEMENTED** only when the repository artifact exists.
A stage is **RUNTIME READY** only when its actual runtime test passes.
A stage is **VERIFIED** only when the relevant evidence is independently checked.
These states must never be collapsed into one status.
