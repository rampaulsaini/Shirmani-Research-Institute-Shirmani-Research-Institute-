1 · चार-स्तरीय production pipeline

L1 · Institute

Research & specification

वास्तविक समस्या, target user, source notes, product name/version और measurable acceptance criteria तय करें।

L2 · Factory

Concrete product build

चलने योग्य module, UI, input/output, sample data और product-specific demo बनाएं। केवल नाम या placeholder को complete product न गिनें।

L3 · QC / release gate

Quality & security checks

Automated tests, dependency review, secret scan, accessibility, error paths और documented limitations. Critical gate fail हो तो release रोकें।

L4 · Showroom / sale

Public listing

Deliverable, price/currency, version, demo, screenshot, usage guide, limitations, support और refund terms स्पष्ट रखें।

Metric rule: “built” के लिए वास्तविक artifact; “QC passed” के लिए test evidence; “live” के लिए deployment evidence; “sold/paid” के लिए वास्तविक order/payment evidence चाहिए। Workflow run अपने-आप product completion नहीं है।

2 · Immediate security baseline

Identity & secrets

  • Least-privilege repository/app permissions.
  • API keys secrets/environment में; source code या logs में नहीं.
  • 2FA/passkeys और जरूरत के अनुसार token rotation.
  • Production credentials public demos से अलग.

Code & dependencies

  • Dependency vulnerability review.
  • Secret scanning/push protection जहाँ उपलब्ध.
  • Static analysis और change review.
  • Third-party Actions versions/SHAs को review और pin करें जहाँ practical.

Runtime & data

  • Input validation, output encoding और rate limits.
  • Personal data minimization, retention और deletion policy.
  • Critical data backups और restore test.
  • Logs में secrets/sensitive content न रखें.

Release & incident response

  • Development, staging और production अलग.
  • Rollback और incident contact लिखित रखें.
  • Public permissions, CORS और integrations की समीक्षा.
  • केवल authorized, scoped security testing करें.

यह recommended baseline है, completed audit नहीं। इस page को जोड़ने से platform अपने-आप secure नहीं होता; repository settings, workflow files, deployment config और actual test results की समीक्षा जरूरी है।

3 · हर product का passport

Identity

Unique ID, finalized name, category, version, owner, release date.

Visuals

अलग product image/screenshot, short on-image description और QR जो long description/guide पर जाए।

Demo

वास्तविक demo video या interactive test drive; inputs, outputs, supported cases और limits.

Quality & sale

Usage guide, QC code, gate result, dispatch state, price, offer validity, support/refund terms.

QR को stable product passport पर ले जाएं। “Verified” केवल तभी लिखें जब उस product का gate record हो। Fake ratings, fake reviews, invented guarantees या fabricated demo outcomes न दिखाएं।
