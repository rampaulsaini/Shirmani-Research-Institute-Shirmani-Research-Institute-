Four presentation versions

  1. V1 · Clear Voice: voice + captions + approved script.
  2. V2 · Presenter Avatar: authorized avatar/photo, scripted voice, reviewed lip-sync.
  3. V3 · Interactive Q&A: questions → context → evidence labels → answer → voice/avatar; uncertain answers fall back safely.
  4. V4 · Live Studio: operator-controlled live session, moderation, source panel, captions, incident/latency log and fallback screen.

These are specifications, not claims that provider integrations or live rendering are already connected.

Product demo storyboard · 60–90 seconds

  1. 0–8s: title, product name and purpose.
  2. 8–20s: real use case and audience.
  3. 20–40s: record actual tool workflow on screen.
  4. 40–55s: show actual sample output and evidence labels.
  5. 55–70s: explain limitations, privacy and authorization.
  6. 70–90s: offer, deliverables, support terms and enquiry link.

Do not use a mockup as proof of a working feature. Label simulated screens “prototype”.

Production acceptance checklist

  • Script is accurate, audience-specific and approved.
  • Factual claims have sources or uncertainty labels.
  • Voice, photo, face and avatar use has recorded authorization.
  • Audio intelligible; captions readable and synchronized.
  • Natural facial movement, gaze and lip-sync reviewed in the actual rendered clip.
  • Mobile playback, accessibility and fallback behavior checked.
  • Privacy, retention, consent and deletion terms are visible.
  • Demo video, VIP screenshot, usage guide, version, price and QR destination attached before sale-ready listing.
  • QC/release/dispatch identifiers generated only after corresponding checks actually pass.
