Micro-Product Usage Guide

Seven browser-based utilities, with practical steps, example inputs, expected outcomes, limitations, and a repeatable demo-recording checklist.

1 · Word & Character Counter

Use: check the approximate length of a draft before submitting an article, application, or website copy.

  1. Open the tool and click or tap the text area.
  2. Paste a short sample such as Hello world. नमस्ते दुनिया।
  3. Compare the displayed word and character counts as you add or remove text.
  4. Try empty input and text with spaces/newlines; note how the tool treats whitespace.

Acceptance check: typing updates the counts; clearing the text returns the counters to the empty-input state.

2 · Percentage Calculator

Use: calculate a percentage, percentage amount, or a change where the tool's supported modes allow it.

  1. Open the tool and read the labels for each input.
  2. For “X% of Y”, enter 15 and 200; the expected result is 30.
  3. Try zero and negative inputs only if supported by the displayed mode.
  4. Check that blank or non-numeric input produces a clear prompt instead of a misleading number.

Acceptance check: the 15% of 200 example returns 30.

3 · Length Unit Converter

Use: convert supported length units for everyday measurements and content work.

  1. Choose the source and destination units shown by the tool.
  2. Enter 1 metre and convert to centimetres if those units are offered.
  3. Expected result: 100 centimetres.
  4. Test a decimal value and verify the displayed rounding.

Acceptance check: conversions follow the supported unit list and invalid values are handled clearly.

4 · JSON Formatter & Validator

Use: format JSON and identify common syntax errors before using data in an application.

  1. Paste valid JSON: {"name":"Shirmani","active":true}
  2. Run the formatter/validator action.
  3. Confirm the output remains valid JSON and is easier to read.
  4. Then remove a closing brace and rerun; the tool should indicate invalid input rather than claiming success.

Acceptance check: valid JSON formats; malformed JSON yields a useful error state.

5 · Color Palette Generator

Use: explore a coordinated set of colors for a design concept.

  1. Open the generator and note the initial palette.
  2. Use the generate/randomize control available in the interface.
  3. Check whether swatches and color values update together.
  4. If copy/export controls are present, test one value and paste it into a text editor.

Acceptance check: every displayed swatch corresponds to its displayed color value; copied values match the swatch.

6 · Simple Digital Drawing Board

Use: make a quick sketch or visual note in the browser.

  1. Open the drawing board on a device with a pointer or touchscreen.
  2. Draw several strokes and check that movement follows the pointer/finger.
  3. Test any clear, color, brush-size, or save/export controls that are actually present.
  4. Refresh the page to learn whether drawings persist; do not promise persistence unless tested.

Acceptance check: strokes render in the expected area and visible controls work as labelled.

7 · Markdown Preview

Use: preview headings, lists, and emphasis before publishing Markdown-based content.

  1. Enter # Heading\n\n**Bold**\n- First item in the editor.
  2. Confirm a heading, bold text, and list appear in the preview.
  3. Try empty input and special characters.
  4. Do not paste sensitive information into a tool unless its data handling has been reviewed.

Acceptance check: preview updates with the input and basic Markdown renders as expected.

Repeatable demo-video & screenshot checklist

  1. Use a clean browser window at a consistent viewport; hide private tabs, account details, notifications, and personal data.
  2. Record the actual tool screen, not a mockup. Show product name, a realistic input, the action, result, and one limitation or error-handling example.
  3. Capture one full-page or full-window screenshot and one close-up of the main result for each tool.
  4. Keep the raw capture, exported MP4, screenshots, and test notes in product-specific folders with version/date metadata.
  5. Playback-check the exported MP4, verify text readability and audio, and ensure the demo matches the current release.
  6. Only then update the product passport with real file paths/URLs, test outcome, version, QC gate, and dispatch state. Never label a placeholder or unrun test as verified.

Suggested naming: SRI-TOOL-001-demo-v1.mp4, SRI-TOOL-001-screen-main.png, SRI-TOOL-001-test-report.md.
