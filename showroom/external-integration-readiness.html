प्रमाण-आधारित स्थिति · 30 अक्टूबर 2026

WhatsApp, Email, UPI, PayPal और Yatharth Mudra

यह पृष्ठ दिखाता है कि वेबसाइट में कौन-सा संपर्क रास्ता मौजूद है और कौन-सी बाहरी सेवा वास्तव में live integration के रूप में प्रमाणित है। लिंक होना, API connection होना, भुगतान प्राप्त होना और भुगतान सत्यापित होना अलग-अलग अवस्थाएँ हैं।

मुख्य नियम: कोई API key, webhook, live account test या transaction receipt उपलब्ध प्रमाण में न होने पर किसी चैनल को “पूरी तरह integrated” नहीं कहा जाएगा। इस पृष्ठ पर कोई secret या निजी credential नहीं रखा जाता।

वर्तमान स्थिति

लिंक मौजूद

WhatsApp

सार्वजनिक सेवा-पृष्ठ पर enquiry link है। यह WhatsApp chat खोलता है; अपने-आप संदेश नहीं भेजता। Business Platform API, webhook और delivery receipt का live test प्रमाणित नहीं है।

Enquiry पेज खोलें
ड्राफ्ट लिंक मौजूद

Email

ईमेल पता/subject/body के साथ mailto draft खुल सकता है। यह स्वचालित ईमेल प्रेषण, inbox monitoring या delivery receipt का प्रमाण नहीं है।

ईमेल संपर्क खोलें
Live checkout प्रमाणित नहीं

UPI

साइट पर UPI निर्देश या payment app link होना live payment integration नहीं है। Merchant VPA, dynamic order reference, server verification और वास्तविक transaction receipt की पुष्टि नहीं हुई है।

जब तक सुरक्षित सत्यापन न जुड़े, भुगतान की पुष्टि manually receipt/bank statement से करें; UPI PIN/OTP कभी साझा न करें।

Live checkout प्रमाणित नहीं

PayPal

इस जाँच में live PayPal checkout, verified webhook, sandbox-to-live release test या प्राप्त भुगतान का प्रमाण नहीं मिला। किसी अनुमानित भुगतान लिंक को live नहीं माना गया है।

भुगतान तभी दर्ज करें जब PayPal खाते में transaction स्वयं सत्यापित हो।

Design / testnet-first

Yatharth Mudra (YTH)

प्रकाशित status record के अनुसार network और contract address नहीं हैं; contract deploy नहीं हुआ, security audit पूरा नहीं और public sale बंद है। इसे अभी भुगतान विकल्प या बिक्री योग्य token के रूप में न दिखाएँ।

यह status specification है, deployed token या monetary value का प्रमाण नहीं।

ग्राहक से भुगतान तक सही क्रम

चरणक्या प्रमाण चाहिएकब पूरा मानें
1. Enquiryग्राहक का संदेश/ईमेल और तारीखवास्तविक संदेश प्राप्त हुआ
2. Proposalकाम का scope, deliverables, समय, revisions और कुल कीमतग्राहक ने लिखित रूप में स्वीकार किया
3. PaymentUPI/PayPal खाते में दिखाई देने वाला वास्तविक transaction recordराशि वास्तव में प्राप्त और संदर्भ संख्या दर्ज
4. Deliveryफाइल/सेवा का delivery link और तारीखसहमत सामग्री ग्राहक तक पहुँची
5. Verificationग्राहक की प्राप्ति/स्वीकृति और अलग payment evidenceप्रत्येक दावा अपने प्रमाण से समर्थित

GitHub Pages static website अकेले secret API keys सुरक्षित नहीं रख सकती और न ही payment webhook की विश्वसनीय server-side verification कर सकती है। वास्तविक automatic integration के लिए सुरक्षित backend/serverless endpoint, provider credentials को secret storage में रखना, webhook signature verification, idempotency, logging और test transactions चाहिए। कोई secret इस repository में commit न करें।

अगला कार्य-क्रम

  1. WhatsApp और email के लिए एक वास्तविक inbound enquiry test करें; test date और परिणाम दर्ज करें।
  2. पहले छोटे paid pilot का scope और कीमत लिखित रूप से तय करें।
  3. UPI/PayPal में से जिस खाते की वास्तविक पहुँच उपलब्ध है, उसके test/live checkout और receipt की जाँच करें।
  4. भुगतान के बाद delivery record और verification जोड़ें; अनुमान को बिक्री न गिनें।
  5. Yatharth Mudra को अलग रखें; deployment और independent security audit से पहले भुगतान के रूप में उपयोग न करें।
