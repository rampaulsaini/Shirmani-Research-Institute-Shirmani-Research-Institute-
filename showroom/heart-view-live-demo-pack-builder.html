3 · Publish checklist

  • Actual product/page opens and core use case works.
  • Demo matches this exact product version.
  • Short on-image description and long description are prepared.
  • Screenshot is captured from the real product UI, not fabricated.
  • QR points to the confirmed public product/usage page.
  • Price, offer, limitations and delivery terms are visible.
  • Voice/avatar rights and consent are documented where relevant.
  • QC defects are fixed before marking release-ready.
Honest readiness: this builder creates text assets only. It does not generate MP4, capture screenshots, create QR images, connect HeyGen, send email/WhatsApp, accept payments, or certify QC. A checklist is not proof that a gate passed.

4 · Four-level production route

  1. Institute: identify user problem, sources and acceptance criteria.
  2. Factory: create the actual tool/product and product-specific demo pack.
  3. QC / Gate: run functional, content, rights, accessibility and release checks; record evidence.
  4. Showroom / Sale: publish the real demo, accurate description, price/quote and enquiry route. Record a sale only after an actual transaction.
