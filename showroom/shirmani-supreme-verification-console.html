सबसे पहले: वास्तविक स्थिति

यह एक काम करने योग्य evidence-tracking console है। यह GitHub/HeyGen से अपने-आप परीक्षण नहीं चलाता और status को स्वयं VERIFIED नहीं बनाता। हर status मानव द्वारा उपलब्ध कराए गए परीक्षण-परिणाम और प्रमाण पर आधारित होना चाहिए। इस पेज पर बदले गए status और notes इसी browser में सहेजे जाते हैं; वे production backend या GitHub में स्वतः sync नहीं होते।

Production rule: वीडियो का लिंक खुलना, API request स्वीकार होना, render पूरा होना, आवाज़ सही होना, lip-sync पास होना और live Q&A चलना अलग-अलग बातें हैं। किसी एक को दूसरे का प्रमाण न मानें।

1. End-to-end chain

Voice / Text→Speech / Transcript→Context + Multi-view→Evidence Gate→Answer→Authorized Voice→Avatar Render→Lip-sync QC→Live Q&A→Audit

हर gate का owner, evidence URL, timestamp, reviewer, failure reason और next action रिकॉर्ड होना चाहिए। Unavailable provider credentials या missing API integration को साफ़ तौर पर BLOCKED / NOT CONNECTED लिखें।

2. Verification gates

Status बदलने के लिए नीचे का control उपयोग करें। “Verified” चुनने से पहले संबंधित वास्तविक प्रमाण और परीक्षण का विवरण भरें। यह dashboard प्रमाण की स्वतंत्र पुष्टि नहीं करता।

G1 · Authorized source assets

मूल portrait/voice का अधिकृत उपयोग; asset identity, consent basis और SHA-256 hash रिकॉर्ड। दोबारा फ़ोटो माँगना इस gate का विकल्प नहीं है—मौजूदा अधिकृत asset record इस्तेमाल करें।

G2 · HeyGen render completed

दिए गए video ID से वास्तविक render status, output URL, resolution, duration और provider response का प्रमाण। Request accepted होना render complete होने के बराबर नहीं।

G3 · Full playback + voice

वीडियो को शुरू से अंत तक चलाना; शब्द, उच्चारण, ध्वनि, clipping, sync drift और अंतिम frame की जाँच। कम-से-कम एक reviewer और test date।

G4 · Lip-sync and face QC

Speech segments पर mouth movement, timing drift, facial consistency, gaze और visible artefacts की documented pass/fail समीक्षा।

G5 · Hindi / English Q&A

कम-से-कम 20 representative questions: सरल/विशेषज्ञ, अस्पष्टता, विरोधी दृष्टिकोण, source request, refusal boundary और “पर्याप्त प्रमाण नहीं” का सही उपयोग।

G6 · Real provider integration

Frontend से authorized backend/API तक request, authentication, response, error handling और secret management। Static preview को live service न माना जाए।

G7 · Live presenter and fallback

Real interactive session, measured latency, reconnect/error path, captions, fallback to text and session termination. No live pass without a real test session.

G8 · Security + deployed truth gate

CI results, secret scanning, access control, data minimization, CSP/dependency review, production URL smoke test and public JSON/status accuracy।

अभी तक कोई local save नहीं किया गया।

4. Auto-work policy

  • Keep: ऐसी जाँचें जो सुरक्षा, ग्राहक सेवा, आय, deployment या वास्तविक उपयोगकर्ता अनुभव सुधारती हों।
  • Throttle: duplicate schedules, identical repeated checks और बिना बदलाव वाली redundant jobs—पहले dependency/owner जाँचें।
  • Never auto-delete: source assets, user content, security workflows, production configuration या unique research artifacts बिना review, backup और recovery plan के।
  • Sales outreach: केवल वैध/सार्वजनिक business contacts, relevant offer, truthful claims, opt-out और rate limits; bulk unsolicited messaging नहीं।
  • Income reporting: enquiry, proposal, accepted scope, payment received और delivered work अलग metrics हैं। अनुमानित बिक्री को revenue न दिखाएँ।

यह policy guide है, repository workflows या email system में अपने-आप लागू किया गया परिवर्तन नहीं।
