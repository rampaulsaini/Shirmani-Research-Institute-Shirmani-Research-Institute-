# SHIRMANI Production-First Conveyor

Purpose: continuously convert catalog identities into customer-facing production work.

## Four levels
1. Institute — research/discovery/specification
2. Factory — concrete digital artifact/module/media
3. QC/Gate — QC code, gate, dispatch state
4. Showroom/Sale — visual, short description, QR, passport, demo, price/offer, order route, reviews

## Production priority
- Concrete product artifact
- Product-specific demo route / MP4 slot
- Product-specific 4K visual
- Product QR / passport
- VIP screenshot
- Usage guide
- Price/offer metadata
- Public showroom route
- Customer review/rating input
- Official-link mapping where applicable

Workflow runs are telemetry, not products. A product counts as produced only when a customer-facing artifact/route exists.

## Continuous mode
The conveyor is designed to continue without requiring a new chat message, subject to GitHub Actions permissions, quota, workflow health, and repository limits.

## Honesty rule
The system must not claim that an MP4, screenshot, external contact, purchase, or third-party relationship exists unless the corresponding asset/event actually exists.
