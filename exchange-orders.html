Exchange Orders

DESIGN SPECIFICATION · NO LIVE EXCHANGE OR PAYMENT EXECUTION

Verified contribution, eligibility और transparent exchange terms को एक auditable order record में संरचित करने वाली परत।

Exchange Flow

Verified / Eligible Contribution → Exchange Order → Counterparty / Service → Human Confirmation → Order State → Settlement Candidate → Audit

यह layer किसी व्यक्ति, ग्राहक, नौकरी, उत्पाद, भुगतान या आय को स्वतः उत्पन्न या सत्यापित नहीं करती।

Order Record

  • order_id — अद्वितीय order reference
  • initiator_reference — initiator का reference
  • counterparty_reference — counterparty का reference, यदि वास्तविक और स्वीकृत हो
  • source_contribution_reference — verified contribution का reference
  • source_allocation_reference — applicable allocation का reference
  • exchange_type — service, skill, product, work या अन्य documented exchange type
  • offered_value / requested_value — प्रस्तावित exchange terms
  • terms — scope, conditions और fulfilment requirements
  • evidence_reference — supporting evidence
  • confirmation_reference — human confirmation record
  • settlement_reference — settlement candidate/result reference
  • audit_reference — audit trail reference

Order States

DRAFT → OPEN → MATCHED → HUMAN_CONFIRMED → FULFILMENT_PENDING → FULFILLED → SETTLEMENT_PENDING → SETTLED

वैकल्पिक governance states: DISPUTED · CANCELLED · ARCHIVED

Integrity Boundary

ELIGIBLE ≠ ORDERED · ORDERED ≠ MATCHED · MATCHED ≠ FULFILLED · FULFILLED ≠ PAID · SETTLED ≠ INCOME CLAIM · ORDER ≠ GUARANTEE

Safeguards

  • कोई invented counterparty, job, product, customer, payment या income नहीं।
  • Automatic matching, payment और settlement disabled.
  • Identity, terms, contracts, payments, disputes और production changes पर human review आवश्यक।
  • Exchange order completed work या payment का proof नहीं है।
  • Privacy boundary: केवल आवश्यक references; अनावश्यक personal data नहीं।
  • Order cancellation और dispute को अलग governance states के रूप में रखा जाता है।
