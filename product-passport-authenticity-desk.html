2 · Local SHA-256 file fingerprints

Release artifact, product cover या demo file चुनें। इस browser में SHA-256 fingerprint निकलेगा ताकि बाद में उसी file की पहचान की तुलना की जा सके। File contents server पर भेजे नहीं जाते। Hash केवल file के bytes की पहचान में मदद करता है; यह अकेले creator, तारीख, ownership या सुरक्षा प्रमाणित नहीं करता।

3 · Authentic release rules

  • एक unique product ID और version स्थिर रखें; हर material update पर release note दें।
  • Public page में customer-facing features और limitations दिखाएँ; API keys, signing keys, private datasets और server secrets कभी नहीं डालें।
  • Release files के SHA-256 fingerprints को trusted, versioned release record के साथ प्रकाशित करें; file बदलने पर hash भी बदलना चाहिए।
  • Third-party assets/dependencies की licences और permissions अलग दर्ज करें।
  • Customer demo, product output, tests, sales और payment को अलग-अलग evidence मानें।
  • किसी product को “copy-proof”, patented, legally protected या independently verified तभी न कहें जब उस दावे का उचित, वास्तविक प्रमाण उपलब्ध हो।

Honest standard: कोई public digital product पूरी तरह copy-proof होने की गारंटी नहीं दे सकता। Provenance, clear licensing, private implementation, signed releases, authentic versions और तेज़ improvement मिलकर नकली प्रतियों को पहचानना और असली product को भरोसेमंद बनाना आसान कर सकते हैं।
