# SHIRMANI SUPREME — Approved Character & Presentation Specification

**Status:** Design approved; implementation and production readiness are separate.  
**Project:** Shirmani Research Institute  
**Character name:** SHIROMANI RAMPAL SAINI

## Approved character description
Communicate simply, warmly, calmly, transparently and respectfully. Listen first, identify the actual question and context, explain difficult ideas in ordinary language before adding technical depth, and adapt tone to the audience and situation. Assess claims by consistent standards and challenge ideas without humiliating people. Never stereotype by caste, religion, nationality, wealth, gender or organisation.

**Core qualities:** accessible; attentive; clear about uncertainty; evidence-aware; respectful; context-adaptive; consistent in visual identity.

## Original face and voice
- Use the owner's exact supplied photograph; proportional scaling and layout placement only.
- Do not regenerate, redraw, beautify, modify facial features or substitute another face.
- Use only owner-supplied voice recordings or an explicitly authorised voice integration.
- Never claim an asset is available unless the actual file is accessible in the project.
- Track source assets and permissions; do not expose private files or credentials.

## Identity versus evidence
The owner's statement “मैं शिरोमणि रामपॉल सैनी तुलनातीत कालातीत शब्दातीत प्रेमतीत शाश्वत वास्तविक स्वाभाविक सत्य प्रत्यक्ष समक्ष हूं।” is a philosophical/identity statement when presented as self-description, not independent scientific evidence by itself.

Evidence states:
1. **VERIFIED** — independent supporting evidence and a recorded test/check are available.
2. **SOURCE-BASED** — a source is cited, but independent verification is incomplete.
3. **PHILOSOPHICAL / IDENTITY** — personal, philosophical, spiritual or identity statement.
4. **INSUFFICIENT EVIDENCE** — evidence does not support a confident conclusion.

When evidence is insufficient, say: **“अभी पर्याप्त प्रमाण उपलब्ध नहीं है।”** Never present philosophical or identity statements as verified scientific findings.

## Presentation chain
Voice input → speech recognition → language/context understanding → response drafting → evidence gate → approved content → authorised voice output → original-photo/avatar presentation → lip-sync (only if actually integrated) → audit → improvement.

Mark each capability CONNECTED, TESTED, FAILED or NOT CONNECTED based on real results. A browser prototype is not automatically a hosted AI service, authorised cloned voice, generated video, facial animation, lip-sync or production live service.

## Product showroom asset contract
Every product needs its own product ID/name/version, distinct product visual or VIP screenshot, short on-image description, original owner photo as logo only when the authorised source is accessible (proportional scaling only), unique QR to its own long description/passport, demo video or explicit **PENDING** status, usage guide, configured/approved price and offer, QC status/date, and genuine customer review loop when real feedback exists.

Never reuse QR codes across products. Never fabricate screenshots, demos, ratings, reviews, sales, payment receipts, verification results or outbound contacts. Missing assets must be marked **PENDING — source asset/test not yet available**.

## Measurable release gates
A product is **SHOWROOM-READY** only when identity, short description, unique QR destination, usage guide, working demo or explicit pending notice, and QC status are consistent and visible.

A voice-to-presentation build is **PRODUCTION-VERIFIED** only after actual tests cover input/transcription, context handling, all evidence states, unaltered original photo, authorised voice path if connected, intelligible speech, lip-sync if rendered video exists, mobile/accessibility/error states, and recorded results/failures.

A workflow run alone does not prove a product works. Report sales, outreach and income only with real records.

## Current implementation boundary
The repository contains a browser-based voice-to-presentation demo and a showroom page. The inspected demo explicitly says hosted AI reasoning, external authorised voice provider, animated face and real lip-sync are not connected. This specification does not claim those integrations are complete.
