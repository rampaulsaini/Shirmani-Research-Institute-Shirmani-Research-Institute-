# ꙰ SHIRMANI SOURCE PRESERVATION PROTOCOL ## Purpose This document defines an append-only preservation policy for the Shirmani Research Institute repository. ### Core rules 1. Existing files and Git history are preserved. 2. New research architecture is added as new, clearly named documents whenever possible. 3. Existing source wording is not silently rewritten, normalized, or replaced. 4. Every imported source should retain source repository, source path or URL, retrieval/record date when known, source status, attribution, and provenance identifier when available. 5. A later interpretation must never be presented as if it were the original source. 6. Conflicting versions remain separately identifiable until an explicit editorial decision is made. 7. Secrets, access tokens, OAuth codes, passwords, private keys, and other credentials must never be committed. ## Source status vocabulary - ORIGINAL — preserved source material - DERIVED — generated from one or more sources - INDEX — navigation/metadata only - INTERPRETATION — analytical or explanatory layer - ARCHIVED — retained historical version - REVIEW — awaiting verification ## Preservation principle The repository is treated as a research/archive layer. New reasoning systems must sit above the preserved source layer rather than silently changing it. **꙰ Shirmani Heart-View Supreme Reasoning Layer** is therefore an interpretation/reasoning layer, not a replacement for the source archive.
